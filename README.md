# AI 短剧编导套装

**把一集剧本变成可以拍、可以改、可以交接的制作方案。**

AI 短剧最贵的，往往不是第一次生成，是回来发现：反打时门跑到了另一边，上段拿在手里的道具下段没了，台词还没说完镜头就切了。片子不对，你却只能盯着一大坨提示词猜：到底该改哪一句？

这套工具厉害的地方，是把原本靠运气的环节拆成了能看、能查、能返工的文件。**开拍前知道每一镜为什么拍；生成前知道哪儿可能接不上；出片后知道是改分镜、修提示词、补镜头，还是在剪辑台上解决。**

## 它好在哪

| 你遇到的问题 | 这套工具怎么处理 | 实际能拿走什么 |
| --- | --- | --- |
| 剧本有情节，却不知道怎么拍才好看 | 六环拆解：开工卡 → 拆戏 → 节拍与情绪 → 空间与机位 → 镜头配方 → 逐镜分镜。先定观众这一拍要知道什么，再定镜头落在说话的人、听话的人，还是关键道具。 | 戏表、节拍表、逐镜分镜、机位图 |
| 明明是同一房间，反打却像换了景 | 用实际引用的场景总览推机位、方向、地标和主光。图里没有的方向先补图，不靠文字硬编。 | 场景卡、方向依据、按需生成的出图清单 |
| 每次改提示词都要复制粘贴，越改越乱 | 译镜把提示词当成可重新编译的产物。改人物卡、场景卡或段落源，再从同一套规则重生成。上一段结束的姿态、位置、手中物和朝向，接到下一段开头。 | 每段提示词、编译报告、可回改的源文件 |
| 台词漏字、没说完、情绪像背稿 | 分镜先定台词在哪一镜、怎么说、听者什么时候反应。译镜按拍安排时长和台词；为台词加秒要在报告里列出来，不悄悄改掉节奏。 | 带时间的台词与表演安排、需确认事项 |
| 成片看着不对，不知道从哪查起 | 把同场同方向的镜头放到一起，看背景和光；再用剪辑质检找夹帧、卡帧和音频切点疑点。工具负责筛，最终由人看片判断。 | 审片报告、拼图、可定位的剪辑问题 |

它不替你决定戏的重音，也不保证视频模型每次都照做。**它把导演的决定留在能改的文件里，把机器能发现的错尽量拦在生成和交付之前。** 对一个人，是少翻几版旧对话；对团队，是换人接手也知道这一集为什么这么拍、下一步该改什么。

## 三项技能，各负责一段

| 你手上有什么 | 用哪个 | 交付什么 |
| --- | --- | --- |
| 剧本、角色图和场景图 | [分镜编导 v6](skills/分镜编导/SKILL.md) | 分镜脚本、场景卡、检查结果；可再画俯视机位图 |
| 已经确认的分镜，需要做成一段段视频 | [译镜 V2.0](skills/译镜/SKILL.md) | 竖屏段落提示词、报告和按需输出的打戏设计单、出图清单 |
| 已生成的视频，或需要检查剪映草稿 | [manju-edit](skills/manju-edit/SKILL.md) | 镜头取舍、剪辑方案、草稿或成片质检；也能按方案新建草稿 |

**可以只用一项。** 已经有分镜就从译镜开始；只有一条 MP4，也能直接用剪辑质检。分镜有竖屏和横屏规则，横屏在文档中标为待验证；下面的整条提示词工作流以 **9:16 竖屏**为主。

## 十分钟上手：先跑一个现成样例

### 1. 下载、解压、检查环境

在解压后的套装根目录打开终端。分镜检查和提示词编译使用 Node.js 18 或更新版本；审片和视频质检用 FFmpeg、ffprobe；语音复核和合成器是可选项。

```sh
node --version
node 检查环境.mjs --试跑
```

第一次优先看分镜检查、机位图、译镜试跑和剪辑查成片。没装语音模型或合成器时，对应项目可以跳过，不耽误分镜和提示词编译。具体缺什么看 [环境安装说明](给另一台电脑的Claude_装环境.md)。

### 2. 安装给 Claude Code 或 Codex（可选）

不想安装也能用：把整个目录交给能访问本地文件的 AI，请它先读 [从这里开始_给AI读.md](从这里开始_给AI读.md)。

Windows PowerShell：

```powershell
& ".\安装到这台电脑.ps1"
& ".\安装到这台电脑.ps1" -Apply
```

macOS / Linux：

```sh
bash 安装到这台电脑.sh
bash 安装到这台电脑.sh --apply
```

第一条只预演，确认安装位置后再执行第二条。同名技能有备份；安装后新开对话。Codex 安装版可用 `fenjing-biandao`、`yijing` 和 `manju-edit` 点名，Claude Code 版使用“分镜编导”“译镜”和 `manju-edit`。

### 3. 不用账号，先把样例从源文件编成提示词

下面的命令只在本地运行。请用一个新的输出目录，不要指向你已有的成品：

```sh
node "skills/译镜/scripts/build.js" "skills/译镜/examples/V2_黑帮圣诞第30集_文戏/源" --bible "附带资料/剧设定_竖屏/黑帮老大的圣诞礼物.md" --out "试跑结果/V2文戏"
node "skills/译镜/scripts/check.js" "试跑结果/V2文戏" --style "附带资料/剧设定_竖屏/黑帮老大的圣诞礼物.md"
```

先打开 `第30集_编译报告.md` 看四段的检查结果，再拿一段输出对照 [样例源文件](skills/译镜/examples/V2_黑帮圣诞第30集_文戏/源/)。重点看三处：**台词在哪一拍、机位是照哪张图定的、这一段停在哪个动作上。** 这三处看明白了，比通读所有规则更快。

现在这份样例会编出 4 段、共 70 秒：0 个错误、1 条 K15 提醒。它指出第 4 段最后一个镜头只拍了东西，观众看不出它接向谁。这个提醒正好演示工具的价值：它不替你选镜头，但能指出**第几段、哪一镜、为什么值得回看**。

## 实战：从剧本到成片

下面用一场虚构的电梯文戏举例：**电梯将关，林岚用手拦门，把装着证据的信封递给周屿，说：“你先看完，再问我。”周屿没回话，手伸到信封前又停住。** 整场戏真正的重音不是一句狠话，是他迟迟没接。用这套工具，可以把这个反应从剧本一直保到剪辑。

### 01｜准备素材，把四件事说清楚

- **画幅与时长**：例如竖屏 9:16、一集约 90 秒；先用一场戏试跑，不必第一遍就做整集。
- **剧本与台词语言**：给本集定稿；有上下集就附上一集结尾和下一集开头。标明普通话、英语等，不能用一种语言的语速替另一种估秒。
- **场景图与角色图**：给实际准备用的总览，最好带俯视格，能看出电梯门、走廊和壁灯的位置。角色图、信封等关键道具也提前对齐。
- **剧设定和主体验证**：给风格、光影质感、固定句和平台上可用的资产名。没有剧设定，可先用 [新剧输入卡](skills/译镜/规则档案/新剧输入卡.md) 定一版，不拿示例剧的风格硬套。

建议每集单独放：`第01集_剧本.md` 和 `第01集_分镜.md` 放在工作目录；该集的 `源/`、`提示词/`、`成片/`、`审片/` 放在 `第01集/` 下面。剧设定和可复用的角色、场景资产放在剧集的公共目录。下文示例命令从套装根目录运行，实际使用时把素材路径换成你的路径。

### 02｜先做分镜，先拍什么比用什么焦段更重要

把上面的素材路径换成自己的，可以这样发给 AI：

```text
用分镜编导（Codex 中可点名 fenjing-biandao）。
读「第01集_剧本.md」定稿。竖屏 9:16，全集约 90 秒，普通话。
场景和角色图在「资产」目录。先只做电梯这场，不写视频提示词。
这场的情绪重音是周屿伸手却没接信封。交开工卡、节拍表、场景卡、
逐镜分镜、台词对账和检查结果。写清每镜从什么状态到什么状态。
```

| 镜头 | 示例时长 | 画面与切点 |
| --- | ---: | --- |
| 1 · 关系镜 | 3 秒 | 先交代门内的人、走廊的人；林岚伸手拦门，切在门停下那一下。 |
| 2 · 林岚中近景 | 5 秒 | 她拿着信封说原台词，镜头给够说完的时间，不急着切。 |
| 3 · 周屿反应 | 4 秒 | 他看向信封，再看林岚；没回话。上一镜的话到这时才有重量。 |
| 4 · 两手与信封 | 3 秒 | 林岚仍拿着信封，周屿伸手尚未接到。停在动作未完成的那一刻。 |

这只是讲思路的示意，实际以你素材里的方向、演员的台词速度和分镜检查为准。**交接前先看**：门在哪边、谁看向谁、灯从哪侧来、台词有没有漏、四镜合起来是否真的拍出了“没接”。

```sh
node "skills/分镜编导/scripts/check_storyboard.js" "第01集_分镜.md" --partial
node "skills/分镜编导/scripts/draw_plan.js" "第01集_分镜.md"
```

只做一场时用 `--partial`；交整集去掉它。机位图出来后，可用浏览器打开 HTML，对照实际总览图核对轴线。

### 03｜译镜写源文件，提示词交给脚本编

换一个对话，把**审过的分镜、剧设定和同一套资产**交过去：

```text
用译镜（Codex 中可点名 yijing）读取已审过的「第01集_分镜.md」
和「电梯试戏_剧设定.md」。按 V2 先做电梯这一段，保留普通话台词原文。
用「资产」里平台实际引用的场景图推方向，图里没有的角度先列为待补。
交集卡、场景卡、人物卡、段1.txt、编译结果和报告。
如果为台词加秒，或下一段需要时间跳，先列出来给我确认。
```

源文件是以后改稿的地方：

| 文件 | 里面放什么 | 出问题先改哪里 |
| --- | --- | --- |
| `集卡.txt` | 剧名、集数、输出前缀等本集信息 | 集数和输出名不一致 |
| `场景卡.txt` | 总览、各方向的依据与地标、光源、场景风格 | 门左右反了、主光变边、补拍缺方向 |
| `人物卡.txt` | 人物简称、外观、状态和资产引用 | 衣服换了、人物引用错了 |
| `段1.txt`、`段2.txt`… | 每段开头和结束状态、镜头、运镜、拍点、台词 | 台词太赶、视线接不上、道具跳手 |

```sh
node "skills/译镜/scripts/build.js" "第01集/源" --bible "电梯试戏_剧设定.md" --out "第01集/提示词"
node "skills/译镜/scripts/check.js" "第01集/提示词" --style "电梯试戏_剧设定.md"
```

输出是每段一个提示词和一份编译报告；需要补方向图时可带出图清单，有武戏设计时另看打戏设计单。**V2 的跨段状态在编译阶段一起检查，别只拿最后导出的几个 TXT 当作验收。** 报告中的 ❌ 改到 0，⚠️ 逐条读，特别留心台词加秒和时间跳。

### 04｜上平台先试一段，别一口气生成整集

1. 建好实际需要的人物、道具和场景总览主体，名字与提示词中的 `@` 对上。先生成刚才的电梯段，观察人物、背景、光和那句台词。
2. 新段可先用总览，不强求每个方向都额外建主体；同场几段背景对不上，或需要补已有镜头，按 [详细使用手册](编导套装_使用手册.md) 第 3 节补对应方向图，并精确引用。
3. 导出按 `段N` 命名，例如 `第01集_段1.mp4`。第一段末尾如果是“周屿手还没碰到信封”，下一段开头就从这个状态接，别直接跳到他已经拆开信封。

生成平台、账号、额度和素材不随套装提供。脚本不会替你把作品上传或生成。

### 05｜看片返工：先找到原因，再决定重生成多少

```sh
node "skills/译镜/scripts/review.js" "第01集/提示词" "第01集/成片" "第01集/审片" --no-asr
```

这是不启用语音识别的跑法。看 `审片报告.md` 和按方向分组的拼图，再人工听原片。装好 faster-whisper 和本地模型后，可用 `--asr-model` 让脚本辅助核对台词，仍不能代替人听。

| 看到的问题 | 先怎么处理 |
| --- | --- |
| 反打时电梯门跑到另一侧 | 回总览和场景卡核对相机方向；必要时补对应方向图。别在最终提示词里加十遍“背景一致”。 |
| 周屿上一段没接信封，下一段突然拿在手里 | 对照两段首尾，补接过信封的动作，或改回一致的状态；两段互相牵连才一起重做。 |
| 台词还没说完就切了 | 核对原文、镜头时长和最后一拍。需要加秒就回分镜确认，再改段落源并重编。 |
| 只在切点闪过一两帧无关画面 | 先逐帧定位素材入点、出点，能在剪辑台处理就别重生成。 |

**别只改导出的提示词。** 临时手改可以用来验证，但有效的改动要回写到源文件，否则下次编译会覆盖你的修正。

### 06｜剪辑交付：不仅要能播放，还要能接着剪

让 `manju-edit` 按分镜把生成段落拆成可用区间：留下哪一拍、切掉哪几帧、对白在哪个入点、哪里只加环境声、哪些镜头必须补。可以先交镜头取舍表，再做可编辑草稿。支持的剪映环境下，按 [草稿方案格式](skills/manju-edit/references/write-draft.md) 先 `--dry-run`，确认后只新建草稿，不覆盖旧工程。

```sh
node "skills/manju-edit/scripts/write_draft.mjs" "第01集/剪辑方案.json" --dry-run
node "skills/manju-edit/scripts/qc_media.mjs" "第01集/成片/第01集_精剪.mp4" --out "第01集/成片质检"
```

最后人工确认：关门的声响有没有盖住对白、周屿伸手前的停顿有没有被剪没、字幕和声音有没有抢拍。机器圈出疑点，**剪辑师决定这一刀要不要留下。**

## 一个人用，和团队用，有什么不同？

- **个人试水**：先跑自带 V2 文戏，再拿自己的 15 秒试戏过一遍。能稳定交出一个场景，再做整集。
- **连续多集**：把剧设定、场景卡、人物卡作为共用资料；各集独立保留分镜、段落源和编译报告。换集可继承设定，换人不必继承一整个聊天记录。
- **团队接力**：导演确认分镜和机位，提示词制作接收已确认的文件，剪辑接收成片、段号和换镜记录。约定只改源文件、不悄悄改原台词、异常在报告里能追溯。
- **只做质检**：不用补整条流水线。手上有成片就先跑 `qc_media.mjs`，有分镜和生成提示词再加译镜审片。
