# 分镜编导

只做一件事：**把一集设计成分镜**。拆戏、定节奏、定空间和机位、按戏型配镜头、逐镜设计景别和运镜，以及每一刀为什么切。

- 2026-10-25 从《惹火私厨》第 34 集的分镜脚本整理出来。导演看完说"基本没问题"（2026-10-22），用户说"本次执行的分镜脚本不错"。这些做法写成了规则，标〔验证·惹火34〕。
- 流程拆成 **6 环**，每环一个文件，写清管什么、规则、产出、验收、出问题时的样子。分镜出了问题，按本页"出问题时找哪一环"那张表找到那一环，只改那一环的文件。
- 两个方向，参数各放一个文件：
  - **竖屏快节奏短剧**（9:16）：两三秒一拍，**已验证**（惹火34）。
  - **横屏精品剧**（16:9）：偏电影，镜头更长、更有呼吸，**待验证**（还没有一集用它拍过）。电影也走这个方向（用户 2026-11-21）。
- **v5（2026-11-21）大版本**：把导演和剪辑师几十年验证过的做法、GitHub 上同类项目和 zenstory 在 Seedance 上的对照实验吃进来（调研全文在 `D:\漫剧公司\精品制作\_分镜编导调研_20261121\分镜编导升级调研.md`）。
  - 规则背后的道理写在 `references/导演方法.md`：规则没写到的情况，按那八条原理推。
  - 新规则都是〔待验证〕或〔导演方法〕，每条在 `测试登记.md` 有一行：从哪来、期望看到什么、怎么测、失败是什么样子。
  - 输出格式没变方向：还是镜头怎么调度、用什么镜头、人在干什么、看向哪、有什么反应。分镜表在最后加了两列，前 7 列一列没动，译镜照旧读。
- **v6（2026-11-24）**：照用户对第 27 集的七条要求和 E27、E30 成片改。环3 v6：方向照平台真正 @ 的总览图俯视格推，图里没有的不设计；站位锚点作废，改成段和段接状态；光源写在画面里；全景写人贴着什么。环5 v7：不写画面上半 / 下半 / 下角（会分屏）；每镜有起点有落点、焦段有变化；不要孤立特写；眼神有由头；段尾停在动作中间；34 个机位术语直接点名。坏的写法和成片图在 `../译镜/反面案例/README.md`，写之前扫一遍。改了什么见 `v6更新说明.md`。
- **环5 v6（2026-11-21）**：每句台词定"说法"（规则 5.25）。按剧本台词分析这一句的情绪，定它是顺、卡、断、一字一顿、拖还是一口气，带标点的台词直接写在"句子功能 / 意图"这一格，译镜照抄。不加列，译镜没动。

## 管什么，不管什么

用户 2026-10-25："这个技能是纯粹用来做分镜脚本的……生成提示词的管穿帮的、管镜头里面人物表演肢体语言具体怎么表达、把分镜转译成提示词，这个是下一个技能（竖屏文戏、武戏编导）去做的，这里就是要把分镜专精设计好。"

| 本技能管 | 交给下一步的提示词技能 |
|---|---|
| 一集拆成几场戏，每场的戏型 | 生成段怎么切、每段几镜、段首段尾 |
| 节拍、情绪、节奏（紧 / 松 / 停） | 穿帮：人物只出现一次、群演、资产行、道具状态 |
| **可拍性（v2 新增）：机位放在模型拍得出来的地方（环3 规则 3.11–3.14）** | 可拍性在提示词阶段再查一遍（P 节） |
| 空间、轴线、视线、机位 | 人物表演、微表情、肢体语言怎么写 |
| 按戏型配镜头：主力景别、景别呼吸、镜头骨架 | 把分镜写成 Seedance 提示词 |
| 逐镜：景别、角度、运镜、镜头怎么引导、切入理由、时长、台词放在哪一镜 | 台词的口音润色、语气写法 |
| **说话的戏要什么**（v4，2026-11-20）：每个说话的人的型、六个维度、强度走向；每句台词的功能、意图和说法；为台词拆镜、留时间（`references/说话戏型谱.md`，环2 规则 2.11–2.14，环5 规则 5.16–5.19、5.25） | 情绪顺序、标点、强度短语怎么写进提示词，扫掉"压着演"的句子（译镜 `手册/7_台词与情绪.md`） |
| **戏的重心和状态**（v5，2026-11-21）：每场戏的重音落在谁脸上、画面曲线、观众知道多少（环2 规则 2.15–2.17）；每镜起 → 止、一镜装几个动作、要紧的先后切开、重音那一刀（环5 规则 5.20–5.23）；覆盖（环4 规则 4.14） | 起 → 止 怎么写成这一段的首尾状态；听的人脸上怎么漏出反应（眼神、呼吸、身体） |

下一步用哪个技能：用户点名译镜就用 `译镜`（竖屏，文戏、武戏、险情都从它进）；没点名时竖屏文戏用 `竖屏文戏编导提示词`，竖屏打戏用 `竖屏武戏编导`；横屏用 `文戏编导提示词`、`武戏编导`。

## 每次必做

1. **先做环0**：方向、单集时长、台词语言、场景资产图，这四件不能猜，没给就先问。读对应的方向文件；项目提供了导演反馈记录就一起读。（v5）开工卡下面贴这一集的剧本原文，一字不改：脚本靠它对台词。
2. **一环一环往下做**：每环做完，对照那一环文件里的"验收"，过了再做下一环。用户要逐环看的，就一环一环交给他看。
3. **照模板写**：`templates/分镜脚本模板.md`。表头不能改，脚本靠表头认列。
4. **交稿前跑脚本**：❌ 全部改掉，⚠️ 保留的逐条在回复里说明为什么。

```
node "D:\漫剧公司\.claude\skills\分镜编导\scripts\check_storyboard.js" <分镜脚本.md>
```

   只写了一部分（比如先交一场戏）时加 `--partial`，不查整集时长和缺的章节。脚本报告按环分组，哪一环报错就回哪一环改。

5. **换成导演的眼睛过一遍**：只看第 5 节的"画面"列，从头到尾在脑子里放一遍（环5 验收最后一条）。
6. （v5，可选）第 3 节写了平面图数据块的，画一张俯视机位图，和分镜一起给导演看：

```

```

7. 规则没写到、或者两条规则打架：看 `references/导演方法.md` 的原理，和下面"规则打架时听谁的"。用了〔待验证〕的新写法，在回复里说一声，测出结果记进 `测试登记.md`。

## 规则打架时听谁的（v5，待用户确认）

一刀好不好要看好几件事，它们会打架。打架时，从排在后面的那件开始让：

1. **拍得出来**：AI 拍不出来的镜头，再动人也没用（3.11–3.14、5.13、5.21、5.22）。
2. **看得懂**：观众知道谁在哪、谁在说、发生了什么（3.5、4.5、4.14）。竖屏观众碎片时间在看，看不懂就划走了。
3. **情绪**：这一刀让观众感到该感到的（2.15、2.16、4.12、5.23）。
4. **节奏**：快慢、松紧对不对（2.4、4.2、4.13）。
5. **视线和轴线连贯**：视线接得上、不越轴（3.5、3.8）。
6. **景别、机位要有变化**（5.4、5.5）。

来源：剪辑师默奇的六条（情绪 > 故事 > 节奏 > 视线 > 画面上的左右方向 > 三维空间），他把情绪排第一。我们改了两处：拍得出来排最前；看得懂排在情绪前面。**"看得懂排在情绪前面"用户还没确认**，详见 `references/导演方法.md` 第八节。

## 怎么迭代一环

- **只改出问题的那一环的文件**。规则编号不重排：新规则接在后面；作废的规则留着，写"作废"和原因。（v2 是第一次使用前的整理，编号重排过一次，以后不再重排。）
- 那一环文件开头的版本号加一，文件末尾的"迭代记录"写一行：日期、问题原话（审片、导演或用户）、改了哪条、为什么。
- 每集分镜脚本的开工卡里记下这次用的各环版本（"环版本"一行）。以后哪集出了问题，查得到是哪一版规则做出来的。
- 规则状态：〔待验证〕的规则，在一集里用过、用户或导演认可后，改成〔验证·剧名集数〕；被证明不行的，改掉，并在条目下写"坑"（写了什么 → 出了什么 → 现在怎么写）。
- 导演或用户的审片意见，原话追加到项目的导演反馈记录，再按上面那张表找到对应的环改规则。
- 一个方向验证出来、对另一个方向也成立的写法，问过用户再同步。
- 能用脚本查的规则，加进 `scripts/check_storyboard.js`，编号和规则一致。
- 改规则先问用户：规则都来自用户和导演的验收。
