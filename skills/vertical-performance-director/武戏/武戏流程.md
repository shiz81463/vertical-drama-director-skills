# 竖屏武戏编导

竖屏（9:16）常规打戏的流程：用户给资产和场景，我设计打法和分镜，照骨架写提示词，用脚本自检，交出一版能直接上平台的提示词。

- 这个技能是 2026-10-22 从横屏原版 `武戏编导`（2026-10-21）改出来的。横屏原版原样保留，16:9 的戏照旧用它。
- 改了什么：构图、轴线、景别的规则按竖屏重写（`rules.md` 里标〔竖屏〕的地方，加上新的 **V 节**）；剧设定改放 `竖屏制作\剧设定\`；检查脚本加了竖屏检查（V0 画幅和宽银幕词、V1 左右排开、V4 TALL FRAME）；看片脚本按竖画面拼图。打法、特效、质感、速度这些和画幅无关的规则一条没动。
- **竖屏还没有一条武戏生成验证过。** 竖屏构图规则来自《废土甜心》竖屏剧集的导演反馈（白模、成片里踩过的坑）和新的推测，都标了来源；第一条竖屏成片出来后，按它去掉"待验证"。
- `examples/` 里放的是比例差打戏的 v13（16:9，天上骑鸟打巨魔，2026-10-19 验证通过），只用来照抄验证过的质感、特效、打斗区块原句；**它的构图和轴线句是横屏的，不能照抄**。第一条竖屏武戏验收通过后，放进 `examples/`。
- 规则只写在 `rules.md` 一处。每条都标了来源：〔v13〕是在巨物天战里验证过的，〔废土甜心〕是竖屏剧集里踩过的坑，〔待验证〕是新加的或改写过的。

## 每次必做

1. **动笔前读** `rules.md`（先看 V 节和 R 节），再定是哪部戏：`竖屏制作\剧设定\` 里有这部戏，就照它抄风格锁、画面质感、特效质感的锁定句；只有横屏剧设定（`精品制作\剧设定\`）的，先做竖屏剧设定；都没有，就是新剧。这两种都走下面的"新剧第一次"。
2. **以骨架为底写**：照 `templates/提示词骨架.txt` 写。标了"照抄"的区块一字不差照抄（区块表在 `rules.md` 的 B 节），只重写这一场特有的部分。
   - **v3 字数和台词（`rules.md` 文末 N 节、Q 节）**：有喊话、对白的段字数落在 **7,000–11,000 的区间**里，过了 14,000 才报 ❌；没有台词的段 7,000–12,000——前十集 15,000 字以上的段台词丢了 30%，最后一镜常被吞。中文已经说过的英文不再说（N2 的重复表）；验证过的打戏句子和特效段 2,000 字下限不动。有喊话时：台词原文只在 Dialogue 行出现一次（Q2），Dialogue 行写起止秒、紧跟在喊的那一拍后面，放在两次交换之间的空当里（Q4）。
   - **v4 场景卡（`rules.md` 文末 X 节）**：同一场戏分好几段时，背景和光会段段不一样（第 10 集前厅证据）。一集开写前先写 `第N集_场景锁.txt`：每场戏的总览资产行、每个方向的背景图资产行（没有人的单方向图，不用多格拼图）、【场景】块（地图、站位锚点、不入画）、每个方向一句 FACING 光句。每段照抄；每镜机位方括号以"方向N"开头。一集写完跑 `node "<本技能目录>/scripts/check_scene.js" <提示词文件夹>`，❌ 改到 0。
3. **交稿前检查，两步**：
   - **跑脚本**，查能数、能对原文的规则。❌ 全部改掉再跑，直到没有 ❌：

```
node "<本技能目录>/武戏/scripts/check_prompt.js" <提示词.txt>
```

   - **跑可拍性检查（v2）**：`node "<本技能目录>/武戏/scripts/check_shootable.js" <提示词.txt>`，❌ 全部改完（规则在 `rules.md` 的 P 节；机位从 `references/配方库.md` 选）。例外只有总控能批。
   - **派审查员**，查要读懂意思的那些：武器在谁手里、打得实不实、物理上做不做得到、视线带不带镜头、特效出处在不在画面里、打戏逻辑、竖屏同框和运动方向、资产齐不齐、人物和场景里的东西会不会多出来等，共 39 项，清单在 `references/审查清单.md`。没有 ❌ 以后，派一个轻量子 agent，只给它文件路径：

```
Agent(subagent_type: "general-purpose", model: "haiku", description: "审查竖屏武戏提示词",
      prompt: "先读 <本技能目录>/武戏/references/审查清单.md，照它审查 <提示词.txt 的完整路径>（有设计单就加上：设计单 <完整路径>）。只读，不改、不建任何文件。按清单里的交回格式交回。")
```

   - 审查员报的每一条，我对照原文核实：属实就改，不属实在回复里一句话说明；它看不准的我来判断。它没报的不等于没问题：交稿前我自己再扫一眼 F 武器、J8 物理、J9 打戏逻辑、V1 同框这几项。
   - 脚本和审查员的 ⚠️，保留的都在回复里用一句话说明为什么。改动大就重跑脚本，必要时再派一次审查员。

## 输入：只问 6 件事

0. **哪部戏**：`竖屏制作\剧设定\` 里有的照用；只有横屏剧设定的、或者新剧，走"新剧第一次"。
1. **多长**：10 秒最多 4 镜，15 秒最多 6 镜，20 秒最多 8 镜。
2. **开场什么状态**：谁带什么伤、在哪、在干什么、兵器在谁手里。
3. **想要什么打法**：高潮是什么、导演的原话。没有就我来设计。
4. **停在哪**：最后一帧谁在哪、什么还没发生；打到最后谁占上风。
5. **资产清单**：场景、人物、群演、兵器道具各有哪些参考图，平台上叫什么名字。我们做片资产通常是齐的：画面里出现的，有资产就都 @（规则 R1）。

第 0、1、2、4、5 件不能猜，没给就先问。其余照下表的默认，交稿时把用了哪些默认列出来，请用户确认：

| 项 | 默认 |
|---|---|
| 平台 | 放哪个项目第几行，先问；画面比例 9:16；分辨率 720p 或 1080p |
| 场景和光 | 场景由用户给。没说光源时，按场景定"有来源的光"（火把、油灯、窗、天光），先把画面写暗 |
| 轴线和同框 | 主角在左、对手在右（左右不越轴）；同框时主角离镜头近、在画面下方，对手远一点、在画面上方，两人连成斜线 |
| 字幕位 | 脸和关键动作放在画面上方约六成以内，下方留给字幕 |
| 接在哪一行后面 | 独立一段 |
| 镜头参考 | 用户给了样片，先用 `scripts/shot_list.js` 拉片，照它的节奏排；没给就按"紧紧松"排 |
| 体型 | 和人差不多大。对手比人大十倍以上，加【体型与比例】（规则 E2）；天上几百米的巨物，改用 `竖屏比例差打戏` |
| 台词语言（有喊话、台词时） | 按剧设定：大部分戏英文；《宁小贤》中文 |
| 资产 | 默认齐全：场景、人物、群演、兵器道具都有参考图，画面里出现的每样一行资产行（R1）；场景写清独一无二的东西在哪、反打时尽头是什么（R2、R6）；群演写这一段几名、在干什么（R4）；每个有名字的角色只出现一次（R3） |

资产的外形以参考图为准。资产行只写尺寸、数量、状态，以及和参考图不一样的地方（规则 E1）；场景、群演、兵器道具的写法见规则 R2–R5。各剧的资产表在它的剧设定里。

## 新剧第一次：先定竖屏剧设定

每部戏的风格锁、画面质感、特效质感都单独做一次，存进竖屏剧设定，之后这部戏的每一行竖屏提示词（文戏、武戏共用）都照抄锁定的句子。

- **已经有横屏剧设定的戏**（现在有《宁小贤》《废土甜心精品》）：拿横屏那份起草竖屏剧设定，风格锁照抄；风格锁里有宽银幕词（如《宁小贤》的"变形宽银幕，2.39:1"），先问用户竖屏要不要保留；画幅写 9:16，状态写"未验证（竖屏）"。用户确认后存进 `竖屏制作\剧设定\<剧名>.md`。
- **新剧**：
  1. 用户填 `templates/新剧输入卡.md`。有风格锁原文，就直接贴原文。
  2. 我按 `references/风格三件套.md` 起草：风格锁、画面质感、特效质感、结尾的英文风格复述和禁止项、这部戏常用特效的定义。竖屏的风格锁不写画幅和宽银幕词。
  3. 自查后给用户确认，英文部分用中文讲清。确认后存成 `竖屏制作\剧设定\<剧名>.md`，状态写"未验证"。
- 第一条生成后只验质感（`references/风格三件套.md` 第七节，竖屏多看一条：有没有上下黑边）。有问题改剧设定，不在单行里补；用户点头后，状态改成"验证过"。

## 流程

1. **收输入**：缺的先问。
2. **设计**（`references/打戏设计.md`），按顺序做：
   - 这一段讲什么；
   - 双方设定；
   - 回合；
   - 秒级攻防表；
   - 打戏逻辑检查；
   - 竖屏空间：俯视站位图，定左右和远近上下，定竖着的地标（第九节）；
   - 分镜：主力景别、紧紧松、打击接力、反应镜头、出招和挨招的正反打、关系镜头接成链；每镜写清同框方式和运动顺着哪条边走。
3. **写提示词**：照骨架写。每镜写五件套；第 2 镜起，第一拍写 Matched on action（"接着上一镜的动作"）；每一下打击写三段：风先到 → 一眨眼的接触 → 力传出去；【镜头衔接】里写 TALL FRAME 一句。
4. **自检**：见"每次必做"第 3 条。
5. **交付**：见下一节。不点生成。
6. **生成后**：
   - 用户把成片下载到本地，我用 `scripts/review_video.js` 抽帧看片，按 `references/平台与看片.md` 写问题表；
   - 只改用户点名的问题，改完再跑检查；
   - 某条写法生成后被用户认可，问过用户再把 `rules.md` 里那条的"待验证"去掉。

## 交付

- **提示词**：存成 `竖屏制作\视频N_名字_提示词.txt`。
- **设计单**：存成 `竖屏制作\视频N_名字_设计.md`。
  - 开头一句：这一段讲什么，打法一句话。
  - 竖屏空间：俯视站位图（用文字画），写清左右、谁近谁远、谁在画面上谁在下、竖着的地标。
  - 正文两张表：
    - **攻防表**：按回合分组。每组先写一句"谁主动 → 对方怎么回应 → 结果把人送到哪"；每行写 秒 / 镜 / 谁 / 动作 / 属于哪种（进攻、闪避、防守、反击、受击）。
    - **分镜表**：镜 / 秒 / 紧或松 / 景别和机位 / 同框方式（纵深、上下、过肩、单人）/ 内容 / 为什么切到这里 / 最可能出错的地方，以及提示词里怎么防。关系镜头的"内容"写清：两边各在哪、兵器什么状态、地标、比上一次变了什么、引出哪一招（规则 H18）。
  - 改版时加"改了什么 / 没动什么"表；用了打击接力或三连放时加剪辑单（H16）；结尾一行写检查结果。
- **回复**（中文、大白话）：
  - 打法一句话；
  - 检查结果：脚本和审查员各报了几个 ❌、几个 ⚠️，怎么处理的；
  - 用了哪些默认，要用户决定的事；
  - 看到了、没改的。
- **提醒上平台四件事**：画面比例设 9:16；时长和提示词一致；分辨率 720p 以上；这一行用到的场景、人物、群演、兵器道具参考图都 @ 上了、名字和平台一致。

## 和别的技能怎么分

| 戏 | 竖屏 9:16 | 横屏 16:9 |
|---|---|---|
| 人对人，或者对手和人差不多大 | 竖屏武戏编导 | `武戏编导` |
| 对手比人大十倍以上，但不是天上几百米的巨物（如伊芙对霜牙） | 竖屏武戏编导，加【体型与比例】 | `武戏编导`，加【体型与比例】 |
| 天上打几百米的巨物 | `竖屏比例差打戏` | `bilicha-daxi` |
| 不打的戏：对话、对视、告别、心事 | `竖屏文戏编导提示词` | `文戏编导提示词` |
| 一段里先说后打 | 拆成两行生成：说的那行用文戏，打的那行用武戏 | 同左 |
| 《废土甜心》竖屏剧集按集做 | storyboard / previs / seedance-prompt（`原项目工作区（未附）`） | — |

## 规则怎么长大

- 看片发现新坑：在 `rules.md` 对应条目下加一行"坑"；没有对应条目就加一条。能用脚本查的，加进 `check_prompt.js`。
- 某条写法生成验证通过、用户点头后，去掉"待验证"；被成片证明不行的，改掉或删掉，并在坑里写清原因。
