# 竖屏编导满血版（v4，2026-11-09）

> **整合包路径**：技能内文件从本文件所在的技能目录定位。`<本技能目录>` 替换成该目录的实际路径；`<项目根目录>` 是当前剧集项目。项目既有目录与规则优先；旧项目资料或案例原片未随包附带时，使用用户明确提供的等效资料。默认交付本地文件，只有当前请求明确要求平台操作时才读取或写入平台。

一个入口写竖屏一段提示词：文戏、武戏、险情、混合段都在这里。底子是竖屏文戏编导提示词和竖屏武戏编导的全部内容（一条没删），上面加了一层**人物表演**，字数落在一个区间里（有台词的文戏 7,000–10,000，8,000 左右最稳），降低台词缺漏的概率。

- **为什么有这一版**：画面已经控得住了，现在台词会说错、少说，表演也偏平。前十集 85 段的语音识别对照：提示词 15,000 字以上的段，台词丢了 30%；以下的只丢 1%。用户实测 8,000 字左右台词基本说对。所以先把字数压下来（N 节），再把省下的字花在具体的表演上（T 节）。
- **和原版比**：组员简化版 v2 和原版竖屏文戏、武戏相比，规则一条没少，只多了 P 节（可拍性）。满血版在它上面：①补了 N 节、Q 节（和小版本一样）；②把文戏、武戏、险情、混合段合到一个入口；③加了表演层 T 节和混合段 M 节；④补了原版的几处缺口（武戏没有台词规则、没有表演规则；灾难戏没有骨架；同一个角色不同人写演法不一样）。
- **验证范围**：场景卡有《320磅》第 29 集的制作记录；表演层仍按原规则里的〔待验证〕标记验收，换项目需抽样试片。

## 每次必做

1. **先定这一段是哪种戏**（选骨架，规则 M 节，在 `表演/rules_表演.md` 末尾）：

| 这一段里有 | 用哪个骨架 | 读哪本规则 |
|---|---|---|
| 只有说话、对视、走动 | `文戏/templates/提示词骨架.txt` | `文戏/rules.md` |
| 说话里夹着一下打（一巴掌、推一把、泼酒） | 文戏骨架，那一下按 M1 写 | `文戏/rules.md` + `武戏/rules.md` 的 D6 |
| 人对人你来我往的打 | `武戏/templates/提示词骨架.txt` | `武戏/rules.md` |
| 摔落、塌陷、坠楼、被救 | `武戏/templates/险情骨架.txt` | `武戏/rules.md` 的 P14 + M2 |
| 先说一大段再打一大段 | 拆成两行；拆不开按 M3 | 两本都读 |

   不管哪种，都要读 `表演/rules_表演.md`（T 节），和那本规则末尾的 P 节（可拍性）、N 节（字数）、Q 节（台词）。

2. **先设计，再写**：
   - 文戏：`文戏/references/文戏设计.md`（节拍、站位、视线、正反打、镜头情绪）；
   - 武戏、险情：`武戏/references/打戏设计.md`（打法、攻防、紧紧松）；
   - 表演：`表演/表演设计.md`：翻人物表演档案 → 抄剧本里所有括号提示 → 在节拍表上排强度档、台词三段、听的人。
   - 设计单写清楚，提示词只负责翻译。

3. **照骨架写，守字数**：
   - 标"照抄"的一字不差（风格锁、剧设定固定句、验证过的英文原句）；
   - **字数是区间，不定死**（N1）：有台词的文戏 7,000–10,000，有台词的武戏、险情 7,000–11,000，没有台词 7,000–12,000；偏短、偏长报 ⚠️，说明一句就行，有台词的过了 14,000 才报 ❌。中文说过的英文不再说（N2）；比区间长了按 N4 的顺序砍，**台词、固定句、Restraint 这类验证过的特效句、可拍性写法不砍**；
   - **v4 场景卡（`rules.md` 文末 X 节）**：同一场戏分好几段时，背景和光会段段不一样（第 10 集前厅证据）。一集开写前先写 `第N集_场景锁.txt`：每场戏的总览资产行、每个方向的背景图资产行（没有人的单方向图，不用多格拼图）、【场景】块（地图、站位锚点、不入画）、每个方向一句 FACING 光句。每段照抄；每镜机位方括号以"方向N"开头。一集写完跑 `node "<本技能目录>/scripts/check_scene.js" <提示词文件夹>`，❌ 改到 0。
   - **台词**：原文只在 Dialogue 行出现一次（Q2）；写台词句数（Q3）；Dialogue 行写起止秒、紧跟在说的那一拍后面（Q4）；
   - **表演**：每人一句档案（T2）；每句台词写说前、说后两拍（T4），听的人在具体那一拍有信号（T5）；语气写声音不写情绪（T6）；剧本括号提示一条不丢（T7）；按强度档写（T9），信号和景别对上（T10），不用坑词（T12）；武戏写 FACES（T13）。

4. **交稿前检查，两步**：
   - **跑一个命令**（自动分辨文戏、武戏、险情；格式、字数、台词、表演、可拍性一起查）。❌ 全部改掉再跑：

```
node "<本技能目录>/scripts/check.js" <提示词.txt>
```

   - **派审查员**查意思层面：文戏用 `文戏/references/审查清单.md`，武戏和险情用 `武戏/references/审查清单.md`，再加 `表演/rules_表演.md` 的 T4、T5、T7、T9 四条。派不了子 agent 时，自己照清单过一遍。
   - 脚本和审查员的 ⚠️，保留的都在回复里一句话说明为什么。

5. **交付**：提示词和设计单照子流程（`文戏/文戏流程.md`、`武戏/武戏流程.md` 的"交付"一节），设计单里多三张表：剧本提示对照表、表演节拍表（加强度档、说前说时说后、听的人）、人物档案句（`表演/表演设计.md` 第二节）。不点生成。

## 输入

照子流程的"输入：只问 7 件事"（`文戏/文戏流程.md` 或 `武戏/武戏流程.md`）。满血版多问一件：**这部戏有没有人物表演档案**（在剧设定里）。没有就先起草，给用户确认（T1）。《320磅》的档案草稿已经放在剧设定末尾，**还没确认**，第一次用时请用户看一眼。

## 规则冲突时听谁的

P 节的裁决表照旧（可拍性 > 剧情台词 > 连续性 > 空间视线 > 表演和镜头情绪 > 质感细节）。字数排在剧情台词之后、连续性之前：超字数先砍质感细节和通用句。表演层（T 节）和文戏 E 节、武戏受击规则冲突时，以 T 节为准。

## 规则怎么长大

- 生成后看片，问题按"是字数、台词、表演、画面哪一类"记下来；表演的问题记到 T 节对应条目下的"坑"。
- 某条写法被成片证明有效、用户点头，去掉"待验证"；被证明不行的，改掉并写清原因。
- 小版本和满血版同时测时，字数、台词的结论两边同步；表演层只在满血版里改。
- 改规则先问用户。
