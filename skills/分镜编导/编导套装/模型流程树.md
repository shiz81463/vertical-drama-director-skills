# 编导套装：模型流程树（给模型读）

> **V2（2026-11-24）：先读 `译镜/手册/0_V2写法.md` 和 `译镜/反面案例/README.md`，和下面打架的以它们为准。** 变了的几处：
>
> - 写分镜之前先下载平台真正 @ 的总览图，在俯视格上推方向（环3 3.25–3.29）；图里没有的方向不设计。
> - 下面说的"站位锚点""方向图精确 @""FACING"是 V1。V2 不锁站位，每段开头接上一段的结尾（账本四格）；补镜头时，承接画面照前一段的结束画面、结束画面照后一段的承接画面写，方向照总览图推。
> - 【结束状态】现在叫【结束画面】；单镜、衔接镜在段落源写 `类型: 衔接`，走编译，不手写骨架。
> - 角度 / 运镜列可以直接点 34 个机位术语的名字（`译镜/手册/8_机位术语.md`）。
> - 改提示词、看片以后发现新的坏写法：加进 `译镜/反面案例/`，跑 `node 译镜/scripts/self_test.js`。

编导套装 V1（2026-11-20）= 分镜编导 + 译镜。这一页是地图：拿到一个任务，从树根往下走，走到哪个节点，就照那个节点去读、去做、在哪停。每个技能具体怎么做，以它自己的 `SKILL.md` 为准，这一页不重复。

分工（用户定）：**分镜编导管这场戏要什么，译镜管怎么写模型才演得出来。** 剧本 → 分镜 → 提示词 → 平台生成（人做）→ 审片 → 哪里出问题回哪里。

路径都相对 skills 文件夹（两个技能并排装在里面）。

## 树

```
收到任务
│
├─ ① 这是不是编导套装的活？
│    ├─ 横屏 16:9、《废土甜心》按集流程、《宁小贤》精品打戏 ──→ 不是。按项目 CLAUDE.md 用别的技能，本页到此为止
│    └─ 竖屏 9:16 短剧 ──→ 往下
│
├─ ② 你是 GPT（GPT-5、GPT-6 系列、Codex 里的 GPT）？
│    └─ 是 ──→ 先读 译镜/GPT/执行规程.md，照它的第 -1 步走（每个阶段停下等用户确认，比本页严）。本页只当地图
│
└─ ③ 手里有什么？从最靠后的那一格进，不重做前面的
     ├─ 只有一个想法，没有台词 ─────────────────→ 停。请用户给剧本；用户明说让你起草，才起草，起草完停下等确认
     ├─ 有剧本，没有分镜 ───────────────────────→ 节点 1 分镜编导
     ├─ 有分镜，缺 3.5 场景卡或机位表"方向"列 ──→ 节点 1b 只补环 3
     ├─ 分镜齐全、用户确认过 ───────────────────→ 节点 2 译镜
     ├─ 提示词写了一部分（源文件夹里有段N.txt）─→ 节点 2，从缺的那一段接着写
     ├─ 已经生成了，成片有问题 ─────────────────→ 节点 4 找病根
     ├─ 已经生成的一集要补镜头 ─────────────────→ 节点 5 补镜头
     └─ 用户手改过提示词，要回写进源文件 ───────→ 节点 6 回写
```

拿不准在哪一格，问用户一句，不猜。

## 节点 1：分镜编导（剧本 → 分镜脚本）

- **进门条件**：四件不能猜的事都有答案：方向（竖屏快节奏短剧 / 横屏精品剧）、单集时长、台词语言、场景资产图（总览或四宫格母版）。缺哪件先问哪件。剧本有几个版本、有扩写版、集数对不上，先问。
- **读**：`分镜编导/SKILL.md`，再按它一环一环读 `环/` 里的文件。有台词的戏读 `references/说话戏型谱.md`。规则没写到、或者两条打架，读 `references/导演方法.md`（v5）。
- **做**：环0 → 环5，每环过了验收再下一环。有台词的戏要有"说话的人"表、节拍表"强度"列、分镜表"句子功能 / 意图"列；第 3 节每场戏要有 3.5 场景卡，机位表要有"方向"列（译镜靠这几样）。
  - （v5）开工卡下面贴剧本原文，一字不改（脚本对台词用）；第 2 节每场戏写重音、画面曲线，揭示、悬念、钩子、追逐的戏写信息差；分镜表最后加"起 → 止"列。第 3 节写了平面图数据块的，跑 `node 分镜编导/scripts/draw_plan.js <分镜脚本.md>` 出俯视机位图，和分镜一起交。
  - （环5 v6）每句台词定"说法"（规则 5.25，`references/说话戏型谱.md` 0.5）：写成 `功能｜意图｜说法`，不是"顺"的直接写出带标点的台词。
- **出门检查**：`node 分镜编导/scripts/check_storyboard.js <分镜脚本.md>`，❌ 改到 0。⚠️ 里的 5.24（台词漏了、改了、多了）逐条看：用户同意删的台词，在回复里列出来。
- **停下**：交分镜脚本，回复照 `分镜编导/SKILL.md` 的"交付"写，建议先给导演看。**不在同一个对话里接着写提示词**，给用户下面的交接口令。

```
用译镜写《<剧名>》第<X>集的提示词。
分镜：<分镜脚本.md 的完整路径>（已确认）
剧设定：D:\漫剧公司\竖屏制作\剧设定\<剧名>.md
源文件夹：D:\漫剧公司\<剧名>\第<X>集总\第三阶段_成片生成\源\
平台上的主体名：<人物、道具、群演、场景总览的 @ 名字；还没建就写"按分镜起名">
这次写：<段1–段N，或者戏1、戏2>
```

## 节点 1b：只补环 3

旧分镜没有场景卡或方向列。只做环 3 的规则 3.15–3.22：每场戏一张场景卡、机位表加"方向"列、站位锚点。别的环不动，剧情和台词不动。跑检查，❌ 改到 0，停下交给用户确认，再给节点 1 那段交接口令。

## 节点 2：译镜（分镜 → 提示词）

- **进门条件**：分镜用户确认过；有 3.5 场景卡和方向列；剧设定在（没有就停，新剧先用 `译镜/规则档案/新剧输入卡.md` 定剧设定，要用户拍板）。
- **读**：`译镜/SKILL.md`（流程、铁规矩、交付）；`手册/1`、`手册/2`；写段时读 `手册/3`；有台词读 `手册/7_台词与情绪.md`；有武戏读 `手册/6`；险情、武戏的键看 `手册/4`。
- **做**：照 `译镜/SKILL.md` 的流程第 1–6 步：建源文件夹 → 集卡、场景卡、人物卡 → 一段一个 `段N.txt` → `build.js` 编译加检查，❌ 改到 0 → 每段照审查清单审（必做）→ 交付。
  - 分镜给了"说话的人"表、"强度"列、"句子功能"列，照着写"情绪"键和问句的标点（手册 7）；没给，自己查 `分镜编导/references/说话戏型谱.md` 补，回复里写"译镜补的，分镜没定"。
  - （环5 v6）"句子功能 / 意图"这一格的第三项是**说法**。写了带标点的台词（如 `卡：He's— he's my fiancé!`、`一字一顿：Get. Out. Now.`），`说` 行的台词框就照这一版抄，标点和重复都不动；写"顺"的，照"台词"列的原文。装不下，回节点 1 让分镜匀秒。
  - 分镜定的做不到（秒数装不下台词、一镜要两张嘴），回节点 1 改分镜，不在译镜里硬塞。
  - （v5）分镜表最后一列"起 → 止"，是每镜开头和结尾的状态：写连续性账本、段首段尾状态时拿它对一遍，别让同一个动作演两遍。分镜标了重音的那一镜（第 2 节"重音"一行，一般是没有台词的反应镜），照分镜给的时长写，不往里塞台词。旧分镜没有这些，照译镜原来的做法。
- **停下**：交提示词和编译报告，回复照 `译镜/SKILL.md` 的"交付"写。编译报告里"要总控批的事"照抄，批之前不上平台。
- **然后是人做的**（你不做，只提醒）：平台上建主体（看下面"@ 规则"）、9:16、时长和提示词一致、点生成。**不上传、不点生成。**

### 一个对话写多少

- 分镜和提示词**永远分两个对话**。
- 译镜一个对话**按场戏写**：同一个场景的几段放在同一个对话里写，前后接得上。整集 5 段以内可以一个对话写完；再多，一个对话写一到两场戏（建议，没验证过哪个数最好）。
- 写到对话该收的地方：先编译，确认已写的段 ❌ 是 0，然后停下，给用户接着写的口令：

```
接着用译镜写《<剧名>》第<X>集的提示词。
源文件夹：<路径>（已写到段<N>，编译过了）
分镜：<路径>
这次写：段<N+1>–段<M>（戏<几>）
```

- 新对话进来：读 `译镜/SKILL.md` 和要用的手册，再读源文件夹里**上一段的"收场"**和场景卡，接着写。已经过了的段不回头改，除非编译报的就是它。

### @ 规则（写资产行时就要想好）

- **新片段**（这一段还没生成过）：平台上只需要建人物、道具、群演和**场景总览**。方向图那几行（`方向N背景 @…：…`）照常编译进去；方向图没出、没建主体时，@ 名字就当普通文字，那一行冒号后面本身写着这个方向能看到什么，模型照总览图和这段文字想象这个方向。
- **补镜头**（已经生成的一集里补，要和前后片段接上）：这一镜所在方向的方向图**必须精确 @**，人物站位照前后片段。没有方向图，先照编译出的 `<前缀>_出图清单.md` 出图，人工校对后再建主体。
- 平台上的主体名和提示词里的 @ 名字一字不差；不一样就改源文件里的 @，重编译。

## 节点 4：成片有问题，找病根

先看病在哪一层，回那一层改，不在下游打补丁：

| 看到的问题 | 回哪 |
|---|---|
| 讲不清、节奏拖、情绪不到位、镜头孤立、越轴、物理上说不通 | 节点 1，按 `分镜编导/SKILL.md`"出问题时找哪一环"那张表找环 |
| 背景和光对不上、穿帮、多出人、台词丢、嘴型错、少切 | 节点 2：改源文件（段N.txt / 场景卡 / 人物卡），重编译。审片照 `译镜/手册/5_看片.md`，先跑 `review.js` |
| 情绪平、问句说成陈述 | 先查分镜给的型和强度（节点 1，环2、环5），再查提示词写法（`译镜/手册/7`） |
| 场景图本身不对（左右反了、有人、光平） | 重出图、校对，不改提示词 |
| 用了分镜编导 v5 的新写法以后变差了 | 节点 1：`分镜编导/测试登记.md` 查那条规则验过没有，记一行测试记录；要退回就删那一条 |

改完只重生成有问题的段；同一场戏里前后有关联的两段（人从站到坐）一起重生成。

## 节点 5：补镜头

- 一段只有一镜：不走编译，照 `译镜/规则档案/骨架/` 里对应戏种的骨架手写，文件名带"单镜"，写完 `node 译镜/scripts/check.js <文件>`。
- **先读前后两段的提示词**：上一段的结束状态（END STATE）、下一段的第一镜，人的姿态、位置、手里的东西要接上；这一镜的方向用这个人身后固定的那个方向（场景卡站位锚点），方向图精确 @。
- 风格锁、固定句、光句照抄同一场戏的段，不自己写。

## 节点 6：回写手改

用户手改了提示词，要回写：拿手改版和编译版逐行比，找出改了哪几处；每一处改到它的源头（哪一块来自场景卡、人物卡还是段落源，看 `编导套装/使用手册_给人看.md` 第 5.1 节；段落源的键名看 `译镜/手册/3_段落源.md`），场景卡里的改动会带到这场戏的每一段，先问用户要不要。重编译，编出来的和手改版逐字比，只差在用户同意的地方。

## 每个节点都守的

- 剧本、分镜里的剧情和台词，用户确认后不改；台词的词和词序不改（可以改标点、紧挨着重复已有的词，见译镜手册 7）。
- 不加剧情、不加有名字的新角色、不替下一集定事。
- ❌ 改到 0，不为过检查删台词、删镜头、删验证过的句子；同一个 ❌ 改两次过不了，报给用户。
- 不上传、不点生成、不点重新生成。
- 回复用中文、大白话，术语第一次出现带一句解释。
- 每个节点结束都停下，写清三件事：做好了什么、放在哪、请用户确认什么，或者下一个对话发什么。
