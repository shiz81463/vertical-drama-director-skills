# 译镜 V2.0（原名 竖屏编导满血版 v5.2，编译式）

> **V2.0（2026-11-24）：先读 `手册/0_V2写法.md`，再扫一遍 `反面案例/README.md`。** 按用户对第 27 集提示词的七条要求改的，E27 v2 和 Gemini 照同一写法做的 E30 成片验证过。要点：不写画面上半 / 下半（会分屏）；固定站位换成【承接画面】【结束画面】；方向照平台真正 @ 的总览图推，图里没有的不用；每镜写构图、光影、落幅，镜头有起点有落点；文戏武戏险情同一套章节；"无配乐"只说一次；字数 7,000–10,000。机位术语 34 个可以直接调用（`手册/8_机位术语.md`）。改了什么见 `V2.0_更新说明.md`。旧集重编写 `格式: V1`。
>
> V1.2（2026-11-20）：台词和情绪。按第 29 集段 5 的对照测试，加了段落源的"情绪"键（强度四档，显以上自动换掉模板里"小而真"那句）、台词可以改标点和重复已有的词、W1–W5 五条检查、`手册/7_台词与情绪.md`。和分镜编导配成编导套装：分镜定这场戏要什么，译镜管怎么写。改了什么见 `V1.2_更新说明.md`。
>
> V1.1（2026-11-19）：拿 E01 补拍审出来的问题补了 8 条自动检查（U1–U8）、文戏也必须照审查清单审、修了"highlights highlights"。见 `V1.1_更新说明.md`。

译镜是个提示词翻译器：把分镜"译"成平台能用的提示词，译的时候把表演和打法一起设计进去。名字读音同"意境"。

> **你是 OpenAI 的 GPT 模型（GPT-5、GPT-6 系列，或者 Codex 里的 GPT）：不管拿到的是一个想法、一个剧本还是分镜，先读 `GPT/执行规程.md`，从它的"第 -1 步"开始一步一步做。** 本页的铁规矩和交付照守，步骤顺序和多出来的检查照规程走。DeepSeek、Claude 等其他模型跳过这一段。

**你只写每一段自己的内容，别的交给脚本。** 一集的提示词由四种源文件编译出来：

| 源文件 | 一集几个 | 写什么 | 手册 |
|---|---|---|---|
| `集卡.txt` | 1 | 哪部剧、第几集、文件名前缀 | `模板/集卡.txt` |
| `场景卡.txt` | 1（每场戏一节） | 这场戏的总览、几个镜头方向（画面左右是什么、光、依据）、地标、场景版风格锁 | `手册/1_场景卡.md` |
| `人物卡.txt` | 1（每人一节） | 每个人、每组群演、每样道具不变的那句资产行 | `手册/2_人物卡和账本.md` |
| `段N.txt` | 每段 1 个 | 这一段的开场收场、表演、机位视线、每个镜头的构图光影落幅、逐拍和台词 | `手册/3_段落源.md` |

脚本负责的事，你不用写、也不用查：

- 风格锁、画面质感、特效质感固定句、结尾固定句：照剧设定贴，一字不差；
- 同一场戏各段的场景文字、背景图资产行、光句：从场景卡贴，各段天生一样；
- 逐拍的起止秒、切点、镜头数、台词行、台词句数：按你写的每拍几秒算出来，不会接不上；
- 每镜的秒数和分镜一不一样：为台词加的秒，自动列进编译报告的"要总控批的事"；
- 【承接画面】【结束画面】从开场收场拼，段和段之间姿态、位置、手里的东西、朝向接不接得上（隔了几段再出现的也查）；
- 音频只挂给这一段说话的人；机位术语展开成固定写法；
- 规则档案里所有能自动查的规则，编译完自动跑一遍。

## 铁规矩

1. 台词的词和词序一字不改。可以改标点、把台词里已有的词紧挨着重复（口吃、哽住），编译报告会列出来；不加 uh、um 这类原文没有的词。不加剧情，不加有名字的新角色。
2. 不上传、不点生成、不点重新生成。
3. ❌ 必须改到 0。不为了过检查删台词、删镜头、删验证过的句子。同一个 ❌ 改两次还过不了，写进"要总控批的事"，接着做别的段。
4. 只改源文件。`scripts/templates/` 里的模板、剧设定、规则档案不改；觉得哪条规则不对，写进"要总控批的事"。
5. 场景图没校对过，不上平台。
6. 镜头时长照分镜。只有有台词的镜可以为台词加秒，加了必须报批：编译报告会列出来，回复里照抄，批之前不上平台。没台词的镜不改时长。
7. 源文件里除了 `#` 注释，每个字都会进提示词：不写画外的人在做什么，不写设计用的档位（intensity 2），不写给人看的备注，场景卡里不写某一镜的事。
8. 武戏不跳过设计。没写讲什么、双方设定、回合、攻防表就写镜头，编译报 ❌；每一下出招都要写对方怎么回应，挨上的每一下都要说得出为什么没防住。

## 交付

- 存到 `第X集总\第三阶段_成片生成\`：每段的提示词、`<前缀>_编译报告.md`（自动生成，里面有每段的字数、检查结果、要总控批的事、平台上要建的主体、连续性账本）。有武戏段时还有 `<前缀>_打戏设计单.md`（自动生成：双方设定、回合、攻防表、分镜）。
- 回复（中文、大白话）：
  1. 几段、总时长，每段是什么戏种；
  2. 检查结果：❌ 几个（应该是 0）、⚠️ 几个，保留的 ⚠️ 一条条说为什么留；审查清单报了几项、怎么处理的（每一段都要有）；有武戏段的，加一句打法（谁靠什么赢了哪一下）；
  3. 和分镜不一样的地方、为了字数砍掉的东西；
  4. 要总控批的事：编译报告"要总控批的事"那几张表照抄（为台词加的秒、时间跳跳过的变化），再加上你觉得不对的规则、改两次还过不了的 ❌、少了或合并了的镜头。没有就写"没有"；
  5. 上平台前要用户做的：画面比例 9:16、时长和提示词一致、每个 @ 的主体都建了。

## 和分镜编导是一套（编导套装 V1，2026-11-20）

用户定的"两边各放一半"：**分镜编导管这场戏要什么，译镜管怎么写模型才演得出来。**

- 两个技能**并排装**在同一个 skills 文件夹里（D:\漫剧公司 和 C:\Users\29849 下的 .claude、.agents，四个地方），一起打包、一起升级。
- 说话的戏归型的那份谱只在 `../分镜编导/references/说话戏型谱.md`。译镜读分镜表；分镜里没有"说话的人"表时才去查谱，不留副本。
- 分镜定的做不到（秒数不够、一镜两句），退回分镜编导改，不在译镜里硬塞。
- 换生成平台：只重测译镜这一半（手册 7、`scripts/templates/情绪.txt`）。
- 还没有分镜、要补镜头、要回写用户手改的提示词，或者拿不准从哪一步做起：读 `../分镜编导/编导套装/模型流程树.md`。给人看的使用手册在 `../分镜编导/编导套装/使用手册_给人看.md`。

## 什么时候翻规则档案

平时不用读。`规则档案/` 是 v4 及以前的全部规则原文和证据（约 20 万字），下面这些时候再去查：

| 什么时候 | 看哪个 |
|---|---|
| 检查报了一个编号，报错那句话没看懂 | `规则档案/README.md` 里按编号找 |
| 打戏的镜头节奏（紧紧松、打击接力、正反打）和竖屏构图要细看 | `规则档案/打戏设计.md` 第六、九节，`武戏规则.md`。打法和攻防的设计不在这里，在必读的 `手册/6_打戏设计.md` |
| 新剧开工，还没有剧设定 | `规则档案/新剧输入卡.md`、`风格三件套.md` |
| 要给人物写表演档案 | `规则档案/表演规则.md`、`人物表演档案模板.md` |
| 机位拍不拍得出来拿不准 | `规则档案/可拍性规则.md`、`配方库.md` |
| 单镜的补拍镜头（一段只有一镜，不走编译） | `规则档案/骨架/` 手写，再用 `check.js` 查 |
| 流程 5a 的语义审查（每段必做） | `规则档案/审查清单_文戏.md`、`审查清单_武戏.md` |
