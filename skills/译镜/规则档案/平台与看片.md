# 平台操作和看片验收（竖屏 9:16）

## 平台基本信息

- 地址：`https://hzxs.aigczy.com:10443`。《宁小贤》早期的行在项目 5622（项目名显示为"废土甜心-第23集"，第 10–22 行）；2026-10-18 起新行在项目 5626（"废土甜心-第27集 剧本"，第 10–17 行是视频 23–26）。新写的行放哪个项目、第几行，先问用户。
- 模型 seedance25；**画面比例设 9:16**：每一行生成前都核对一遍，沿用横屏项目、复制横屏行时比例可能还停在 16:9。时长、比例、分辨率在平台参数里设，不写进提示词；提示词的时间轴必须和平台时长一致。**分辨率选 720p 或 1080p**（竖屏是 720×1280 或 1080×1920）：v12 第 1 次成片是 854×480，雨丝、颗粒、毛孔都出不来。
- **单行提示词上限 20,000 字**，平台计数 = 字符数 + 每个 @引用多 1（存成 `@名字#`）。
- **不点"生成""重新生成"**，由用户点。上传文件由用户做。下载要先问。

## 被平台拦了（版权、违规）

- **先原样再生成一次。** 拦截有随机性：E27 段 1 被判"可能涉及版权"，成片里用的正是被拦前那种构图。
- 还拦：一次只改一处再试，记下改哪处才过。顺序：风格锁和结尾句里的片名、平台名 → 画面里的字、牌子、商标 → 像名场面的构图 → 参考图本身。
- 不凭一次拦截就改构图、改台词。查到确实是哪一处，才写进规则（反面案例 22）。

## 引用怎么写

- 角色资产：`@资产名`，在编辑器里是 mentionRef 节点 `{value: 名字, label: 名字}`。
- 本行上传的图：`$图片N`，在编辑器里是 assetRef 节点 `{fileId, refType:'image', label:'$图片N'}`。改写时**保留原来的 fileId**。编号按这一行参考图的顺序，每一行各自编号。
- **资产库里改了名字，提示词里的旧 `@名字#` 会变成 is-missing（参考断开）**，必须把 mention 改成新名字（2026-10-16：小孩 → 女子）。
- 检查是否断开：编辑框里的引用芯片带 `is-missing` 类就是断了。
- 资产行不再描述外形，全靠参考图（规则 E1），所以这一行的图一定要传齐。

## 用浏览器写入一行（Tiptap 编辑器）

1. 读当前内容：`[...document.querySelectorAll('.storyboard-editor__surface')][行号-1].editor.getJSON()`，把段落用 `\n` 连起来（mention → `@label`，assetRef → label），算长度和 hash（djb2-xor：h 从 5381 开始，`h=((h*33)^c)>>>0`），确认平台上是你以为的那一版。
2. 在页面里做字符串替换（每条替换必须恰好出现 1 次），把结果存到 `window.__rawXX`，并滚动到该行、算出编辑框坐标（CSS 坐标 × 0.7805 = 截图坐标）。
3. **同一个 batch 里**：双击编辑框进入编辑 → 用正则把文字拆成 text / mentionRef / assetRef 节点 → `editor.commands.setContent(doc, {emitUpdate:true})`（第二个参数必须是对象，写 `true` 不保存）。编辑器很快会退出编辑状态，所以要先把文字存进 window，再双击加写入一起做。
4. 真实点击编辑框外面（表头空白处）触发保存（网络里出现 `storyboard/batchUpdate`）。用 find 找表头"分镜号"拿 ref 去点；不要点顶栏的项目标题，浏览器窄的时候那个位置是按钮，会弹出"版本公告"，编辑框失焦却不保存。
   - **一次只 setContent 一次，内容就是最终正文**。不要为了"制造变化"先写占位字再写正文：平台保存的是第一次更新，2026-10-18 第 17 行因此被存成了一个字符"x"。没触发保存就重新双击进入编辑，再 setContent 一次正文。
5. 刷新页面，再读一次，核对长度、hash、引用芯片都对。一次页面加载只改一行。
6. 本地保存一份同样的文本，脚本里算出相同的 hash。

## 看片

### 用户把成片下载到本地时（首选）

运行：

```
node <本技能>/scripts/review_video.js <视频.mp4> <输出文件夹>
```

脚本会做四件事：读时长、分辨率和帧率（成片不是竖的会提醒：多半是平台比例没设成 9:16）；用画面变化分数找实际切点；每 0.5 秒抽一张，拼成带时间码的宫格图（竖画面一张 8×2 格）；在每个切点前后每 0.125 秒抽一张，拼成一张图。然后用 Read 打开这些图逐张看。

- 实际切点和提示词里写的切点对比，就知道模型有没有按镜头切、哪个镜头被合并了。
- 切点前后的密集帧，专门看衔接：动作有没有倒回重演、方向有没有反、有没有跳过一拍。
- 看质感和比例时，加 `--frames 0,6,11` 抽几张全分辨率单帧放大看。
- 拿用户给的参考视频对照时，对参考视频也跑一次，并排看宫格图（v12 就是这样和"打斗参考"对照，找出缺运动模糊、缺空气里的东西、缺打击爆点）。

### 在平台上看（没有下载时）

- 打开该行视频抽屉：在行里找 aria-label 为"播放视频"的按钮，用 JS 点它（不要按坐标点，旁边紧挨着的是"重新生成视频"）。
- 抽屉顶部是最新一次生成；历史列表里标着"第 N 次生成"和时间。看旧版本时把鼠标移到缩略图上，点出现的播放图标（不要点旁边的循环箭头）。
- 抽帧：`v.pause(); v.currentTime=t;` 等 `seeked` 事件后再等约 0.9 秒，然后截取视频区域的图。

### 写问题表

格式：时间 / 画面 / 问题 / 原因（追到提示词里的哪句话）/ 改法。只改用户点名的问题，其余写进"看到了、没改的"（规则 A2）。改完重新跑 `check_prompt.js`。

## 验收清单（竖屏文戏）

竖屏先看这四条：

- 画幅：成片是不是竖的（720×1280 或 1080×1920）；有没有上下黑边，或者一块横画面塞在竖画面中间
- 同框：两个人是不是左右挤在画面两边、中间一片空；同框时谁近谁远、谁上谁下，前后镜头一致吗（规则 V1、V2）
- 脸和字幕位：脸是不是在画面上方约六成以内；特写的脸有没有被画框切掉；过肩的前景有没有挡住说话人的脸（规则 V3、V8）
- 视线：单人镜头里视线擦着镜头边往画面左或右看，和对方那一镜对得上；往上看的镜头有没有一路仰到天上（规则 F3、E9）

再照横屏的清单看：

- 画面质感：暗不暗；颜色是不是项目的色调（《宁小贤》是暖琥珀，暗部带青绿）；空气里有没有东西（雾、浮尘、灯烟）；脸是真皮肤还是塑料脸；像不像 CG
- 光：光是不是从说好的光源来；谁在光里、谁在暗里对不对；光的变化有没有画面里的原因
- 视线：两个人看对方时，方向是不是一左一右对得上；高低对不对；有没有人对着空处看；有没有人看镜头
- 轴线：谁在左、谁在右，整段有没有换过来
- 正反打：两边景别是不是同级；切过去能不能接上（像不像在对视）；转折之后有没有再同框
- 表演：表演是不是太大（做鬼脸、嚎哭），或者是一张面具脸；听的人是不是木头脸；关键反应有没有"本能 → 漏出来 → 压回去"
- 嘴型：只有说话的人嘴在动；画外音时画面里的人嘴唇不动；台词说完了没有、有没有被加速
- 变化的时间：眼泪、换手的东西是不是在对的那一镜才出现，没有从第一帧就挂着
- 镜头：运镜是不是跟着情绪动；有没有乱晃、乱推；情绪最高点有没有停住；有没有慢镜头
- 有没有字幕、文字；眼睛发不发光；人数对不对；背影人物有没有转成正脸
- 结尾是否停在悬点上，和【结束状态】一致
