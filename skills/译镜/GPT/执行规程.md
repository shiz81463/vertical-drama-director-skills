# 译镜 GPT 执行规程

> **V2（2026-11-24）：先读 `手册/0_V2写法.md`，和这份规程打架的地方以它为准。** 不再写站位、锚点、方向背景图（写了报 ❌ X13）；G9、G10、X6、镜头里的 `Cut on the look` 不适用。换成：先照平台总览图的俯视格推方向（手册 1）、每人写开场收场四格（手册 2）、每镜写构图、光影、落幅（手册 3）。G19 在 V2 只提醒（眼神光可以写）。反面案例先扫一遍（`反面案例/README.md`）。这套 GPT 规程配 V2 还没完整跑过一集，跑完把问题告诉总控。
**只给 OpenAI 的 GPT 模型用**（GPT-5、GPT-6 系列、Codex 里的 GPT 都算）。DeepSeek、Claude 不读这一页，照 SKILL.md 做。

2026-11-18 加。用户反馈 GPT 用译镜写的提示词有三个毛病：
- 多段之间场景接不上，一大半是严重穿帮；
- 到处发光，眼睛也发光；
- 照着范例的样子填键，不推理。

根子是**每一段各想各的**：方向、谁看画面哪边，每写一段都重新想一遍，想得不一样，两段剪在一起就穿帮。

办法：
- **先看手里有什么，从对应的那一步开始**，每一步做完停下来给用户确认；
- **全集的方向和视线先在工作单里一次定死**，而且必须照真的分镜定；
- **写每一段只查表、不重新想**；
- **编译时脚本拿每一段对工作单、拿工作单对分镜**；
- **编译过了还要照审查清单审一遍**（V1.1 加）：脚本只查字面，意思上的矛盾（看不看得见、人有没有瞬移、台词对谁说、前后段接不接得上）只有审查能抓。

## 一、八条硬规矩（SKILL.md 的铁规矩照守，这八条是多出来的）

1. **先看手里有什么（第 -1 步），不跳步。** 不管拿到的是一个想法、一个剧本还是分镜，都不许直接写提示词。也不许用 `seedance25-prompt-optimizer`，或者任何"优化提示词""扩写提示词"的技能，把想法直接写成提示词。没有合格的分镜，编译过不去（G22–G24）。
2. **先工作单，后段落源。** 第一关没过，不写段1。
3. **写一段只看六样东西：**
   - 分镜里这一段的几镜；
   - 工作单里这一段那一行；
   - 这场戏的轴线；
   - 场景卡这一场；
   - 人物卡；
   - 上一段的"收场"。

   别的不看：不翻规则档案（报错编号指过去，才查那一条）；不读别的编导技能（竖屏文戏编导提示词、竖屏武戏编导、文戏编导提示词、武戏编导，它们和译镜写法不同，混着用就乱）；不回头重读手册。
4. **方向号、视线、分镜秒、台词都照表抄。** 方向和视线照工作单，分镜秒和台词照分镜。背景只靠方向号，机位里不写背景里有什么。每镜写"主体"。
5. **不写发光。** 段落源里不出现这些词：
   - 英文：glow、glowing、radiant、luminous、shimmer、aura、ethereal、eyes shine、eyes light up；
   - 中文：发光、光芒、光晕、眼里有光。

   否定句也不写，比如 never glow、不发光：风格锁的负面词已经管了，你再提一次，反而把"发光"带进画面。情绪写身体信号：眼睛停在哪、呼吸、喉咙、手。光只写在场景卡里。
6. **范例只看格式。** 范例的句子一句不抄，脚本会查：连着 40 个字一样就算抄。
7. **做到哪写在文件里，不靠记性。** 上下文被压缩、换了新对话，先读这几个文件：`源\工作单.txt`、`<前缀>_GPT进度.md`、`<前缀>_编译报告.md`，有 `<前缀>_审查记录.md` 也读。从进度文件里的"下一步"接着做。
8. **编译过了不等于做完，每段都要审（V1.1）。** 全集 ❌ 改到 0 以后，进度文件的"下一步"会写"审查段……"：照第 2.5 步审，审完记进 `<前缀>_审查记录.md`。进度表每段有一个"指纹"，审过的段把指纹抄进记录；段落源改过、重编以后指纹会变，那一段要重审。进度文件写"全集都过了，也都审过了"，才交付。

## 二、GPT 模式怎么开

**源文件夹里有 `工作单.txt`，编译就自动进 GPT 模式。** 集卡里再加一行 `模型: GPT` 也行，两样有一样就开。

编译命令不变（技能装在别处，就换成那里的路径）：

```
node "D:\漫剧公司\.claude\skills\译镜\scripts\build.js" "<第X集总\第三阶段_成片生成\源>"
```

开了以后脚本会多做这些事：
- 多查工作单、分镜和 G1–G31；
- 有几个 ⚠️ 升成 ❌；
- 每次编译出一份 `<前缀>_GPT进度.md`；
- 源文件夹里还没有段落源时，只查第一关。

提示词本身和不开 GPT 模式时一模一样，只是检查更严。

## 三、步骤

### 第 -1 步：看手里有什么（入口分流）

| 手里有什么 | 怎么认 | 先做什么 | 做完停下来，交给用户确认什么 |
|---|---|---|---|
| 只有一个想法 | 没有分场、没有台词 | 先写剧本：几场戏、每场在哪、谁在场、每句台词。存成 `第X集总\剧本_草稿.md` | **剧本。** 用户没说确认，不往下做分镜 |
| 有剧本，没有分镜 | 有台词，没有分镜表 | 用**分镜编导**做分镜，6 环照它的流程走。第 3 节必须有每场戏的场景卡（"#### 场景卡：地方，时段"），机位表必须有"方向"一列。跑分镜编导的检查，❌ 改到 0 | **分镜**（最好先给导演看） |
| 有分镜，但缺场景卡或机位表没有"方向"列 | 旧格式的分镜，编译会报 G24 | 用分镜编导只补环3：场景卡和方向（规则 3.15–3.17），别的环不动。跑检查，❌ 改到 0 | **补上的场景卡和方向** |
| 分镜齐全 | 有场景卡、方向列、分镜表 | 从第 0 步开始 | 最后交提示词 |

"停下来"的意思：这一轮回复就写清三件事，然后不再往下做：
- 做好了什么；
- 放在哪；
- 请用户确认，确认了下一步做什么。

用户说"确认""可以""继续"之后，才进下一行。剧本、分镜里的剧情和台词，用户确认后就不再改。

### 第 0 步：读（只读这些，按这个顺序）

| 读什么 | 要从里面拿什么 |
|---|---|
| 本页 | 全部 |
| `SKILL.md` | 只读"铁规矩"和"交付"两节 |
| `手册/1_场景卡.md` | 场景卡每个键怎么写 |
| `手册/2_人物卡和账本.md` | 人物卡、开场、收场 |
| `手册/3_段落源.md` | 段落源每个键怎么写、常见报错 |
| `手册/7_台词与情绪.md` | 有台词时读：分镜的"说话的人"表怎么用、问句的标点和尾音、"情绪"键、往回收的词 |
| `手册/4_戏种.md`、`手册/6_打戏设计.md` | 只在这一集有武戏或险情时读 |
| 这一集的分镜脚本 | 3.4 机位表的"方向"列、3.5 场景卡、第 5 节分镜表（每镜几秒、机位、台词） |
| `竖屏制作\剧设定\<剧名>.md` | 人物表演档案 |
| `examples/320磅第29集/源/段2.txt`，以及编译出来的段 2 | **只看格式**：键怎么写、编译出来长什么样 |

### 第 1 步：全集一次定死（第一关）

1. 建 `第X集总\第三阶段_成片生成\源\`，把下面几个文件拷进去：
   - `模板/` 里的集卡、场景卡、人物卡；
   - `GPT/工作单模板.txt`，改名 `工作单.txt`。
2. 写集卡、场景卡、人物卡。场景卡照分镜 3.5 节：场景名、方向号、背景图的 @ 名字和分镜一字不差（G31 会查）。
3. 写工作单。**第一行写分镜的完整路径**：`分镜: D:\…\第X集_分镜脚本.md`。然后按顺序想清这四件事，答案写进对应的地方：

| 想什么 | 答案写在哪 |
|---|---|
| ① 这一集分几段，每段是分镜里的哪几镜？照分镜切点分段：一段 15–20 秒、最多 5 镜、一段只在一个场景里。每镜的方向，照分镜里这一镜的机位、在机位表里查"方向"那一列。分镜的每一镜都排进某一段，不合并、不拆分、不调换顺序 | 工作单"段表"，一段一行 |
| ② 每场戏里，谁和谁对看、对话？A 看 B 时眼睛朝画面哪边？站在镜头这一边看平面图：A 在左、B 在右，A 看 B 就是 screen-RIGHT，B 看 A 就是 screen-LEFT。对看的两个人一定一左一右。分镜 3.3 方位表写了视线的，照它 | 工作单这场戏的"轴线"，每对人写两行 |
| ③ 对看的两个人，身后各是哪个方向？一般是相反的两头。同一个人的单人镜头，在这场戏的每一段都朝同一个方向 | 场景卡的"锚点"，照分镜 3.5 的站位锚点 |
| ④ 这场戏里有没有人走到另一边？没有就什么都不写；有，写清从哪一段起、为什么 | 工作单的"换轴"，场景卡锚点加上新方向 |

4. 编译。还没有段落源时，脚本只查第一关：工作单、分镜、场景卡、人物卡。❌ 改到 0，才进第 2 步。

### 第 2 步：一段一段写（每段一轮）

1. 读 `<前缀>_GPT进度.md` 里的"下一步"，它告诉你写哪一段、这一段每镜的方向。
2. 只看硬规矩第 3 条那六样，写 `段N.txt`。格式照手册 3。每一镜写完，对一遍：

| 项 | 怎么写 |
|---|---|
| 机位第二格 | = 段表里这一镜的方向号 |
| 机位第三格 | 只写镜头站在哪、多高，谁在画面哪里。**不写背景里有什么**；要提背景，只写"背景是方向N，虚掉" |
| 主体 | 拍的是谁（人物键）；拍手、拍东西、拍全场写"无" |
| 分镜秒 | = 分镜表里这一镜的"时长"。为台词加的秒写在拍里，脚本会列出来报批 |
| 说 | 台词照分镜原文抄，词和词序一字不改（可以改标点、把已有的词紧挨着重复，见手册 7）。分镜这几镜里有几句就写几句，不多不少 |
| 情绪 | 分镜有"说话的人"表和节拍表"强度"列的，照它写在"说"的上一行（手册 7）；没有就查 `../分镜编导/references/说话戏型谱.md` 补，回复里说"译镜补的" |
| 视线 | 照这场戏的轴线抄：`Wendy looks screen-RIGHT ... toward Ethan`。看人时一定写名字，写 at her 脚本就没法核对 |
| 开场 | 同一场戏、没写"衔接: 时间跳"时，和上一段的"收场"一字不差 |
| 状态 | 这一段里谁的姿态、位置、手里的东西变了，从第几镜起 |
| 拍 | 只写人：位置、视线、身体信号。不写背景里有什么、不写光、不写发光一类的词 |

3. 编译，❌ 改到 0，改的是源文件。同一个 ❌ 改两次还过不了，写进"要总控批的事"，接着写下一段。
4. 已经过了的段不回头改，除非编译报的就是那一段（比如 L1 接不上）。也不再读它的全文，只读它的"收场"。

### 第 2.5 步：审查（V1.1 起每段必做）

全集编译到 ❌ 0 以后，进度文件的"下一步"会写"审查段……"。每一段照审查清单审一遍：武戏用 `规则档案/审查清单_武戏.md`，文戏和险情用 `规则档案/审查清单_文戏.md`。能派子代理就派，把这一集提示词所在的文件夹也给它，它要读前一段和后一段（清单第 47–51 项）；不能派就自己读。这一步是第 2 步第 4 条"不再读过了的段"的例外。

1. 审出来的 ❌ 回到源文件改，再编译。改过的段指纹会变，进度表会写"改过，要重审"。
2. 审完一段，在 `<前缀>_审查记录.md`（和提示词放在一起，没有就新建）里写一行：

   ```
   | 段 | 指纹 | 审出 | 怎么处理的 |
   |---|---|---|---|
   | 段3 | a38cf972 | ❌ 0、⚠️ 2 | 两条 ⚠️ 留着：…… |
   ```

   指纹照进度表抄，一个字不改。不审就抄指纹，等于没审：用户会拿审查记录对成片。
3. 再编译一次。进度文件写"全集都过了，也都审过了"，进第 3 步。

### 第 3 步：交付

照 SKILL.md 的"交付"写回复，第 2 条后面再加两句：GPT 模式的 G 检查 ❌ 几个（应该是 0）、⚠️ 几个，保留的 ⚠️ 为什么留；审查记录里每段审出几条、怎么处理的。

## 四、GPT 模式多查的

| 编号 | 查什么 | 报了怎么改 |
|---|---|---|
| G1 | 源文件夹里有没有 `工作单.txt` | 从 `GPT/工作单模板.txt` 拷过去，填完 |
| G2–G5 | 段表：不是空的，段号连着排，场景和方向都在场景卡里 | 照报错改段表；缺方向先加进场景卡，再出这个方向的图 |
| G6–G8 | 轴线：场景名、人物键对得上；对看的两个人一左一右 | 对看写成同一边就是越轴，改掉一边 |
| G9 ⚠️ | 对看的两个人锚点是同一个方向 | 一般改成相反的两头，不然正反打的两个单人镜头背景一样 |
| G10 ⚠️ | 有两个以上的人有锚点，这场戏却没写轴线 | 有人对看就写；真没有，写一行 # 注释说明 |
| G11 | 换轴写得不对 | 先有轴线，再写从哪一段换 |
| G12–G14 | 段落源和段表：场景一样、镜头数一样、每镜方向一样 | 照段表改；段表本身错了，先改段表 |
| G15 | 每镜写了"主体" | 补上；拍手、拍东西写"无" |
| G16 | 机位里写了背景 | 删掉，或者只写"背景是方向N，虚掉" |
| G17、G18 | "视线"里谁看谁朝哪边，和轴线一样 | 照轴线抄；人真换了边，写"换轴" |
| G19 | 发光一类的词 | 换成身体信号；光留在场景卡 |
| G20 | 照抄范例的句子 | 按这一集的分镜重写 |
| G21 ⚠️ | 拍里写了背景有什么 | 删掉；真要写，和场景卡这个方向的"背景"一样 |
| G22 | 工作单写了分镜的路径，文件找得到 | 第一行写 `分镜: 完整路径`；手里没有分镜，回第 -1 步 |
| G23 | 分镜过了分镜编导的检查 | 用分镜编导改到 0 ❌，给用户确认 |
| G24 | 分镜有场景卡、机位表有"方向"列、有分镜表 | 旧格式的分镜：用分镜编导补环3，给用户确认 |
| G25–G27 | 段表的分镜镜号都在分镜里；每镜只排一次、顺序不乱、一镜不漏；镜头数和分镜一样 | 照分镜排；真要合并或删镜头，写进"要总控批的事" |
| G28 | 段表每镜的方向 = 分镜里这一镜机位的方向 | 照分镜的机位表抄 |
| G29 | 段落源的分镜秒 = 分镜里这一镜的时长 | 照分镜抄 |
| G30 | 台词和分镜一样：一句不少、一句不多、词一字不改（V1.2 起标点和紧挨着的重复不算改） | 照分镜原文抄进"说" |
| G31 | 场景卡.txt 的场景名、方向号、背景图名和分镜 3.5 一样 | 照分镜改场景卡 |

| 编号 | 是什么 |
|---|---|
| X6 | 方向和锚点对不上 |
| L2、L3 | 没写开场；变化没写进"状态" |
| F3 | 拍里的视线和"视线"不一样 |
| E7 | 会带出发光眼睛的强情绪词 |

## 五、约束句怎么写才管用

- **写看得见的事实，不写口号。** 不写"保持一致""不要穿帮"；写"Ana is always seen with the bookshelves behind her"这种画面里看得见的事（名字和东西换成这一集的）。
- **一件事只在一个地方写：**
  - 背景和光 → 场景卡；
  - 人不变的样子 → 人物卡；
  - 这一段才有的变化 → "状态"；
  - 谁看哪边 → "视线"。

  同一件事写在三个地方，每处写法稍有不同，模型就会挑其中一个，每段挑的还不一样。
- **不靠否定句提醒模型。** "her eyes do not glow""no window behind her"会把 glow、window 带进画面。不想要的东西就不提它，风格锁的负面词已经管了。〔待验证：这是 GPT 模式的预防写法，还没有成片对比过〕
- **两个同性别的人在一句话里，用名字，不用 he / she**（检查 I4）。
