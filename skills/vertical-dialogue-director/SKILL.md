# 竖屏文戏编导提示词

> **整合包路径**：技能内文件从本文件所在的技能目录定位。`<本技能目录>` 替换成该目录的实际路径；`<项目根目录>` 是当前剧集项目。项目既有目录与规则优先；旧项目资料或案例原片未随包附带时，使用用户明确提供的等效资料。默认交付本地文件，只有当前请求明确要求平台操作时才读取或写入平台。

竖屏（9:16）文戏要做到两件事：人物会表达情绪，镜头也会表达情绪。用户给资产、场景和台词，我拆节拍、定站位和视线、排正反打、写微表情和镜头，照骨架写提示词，用脚本自检，交出能直接上平台的一版。

- 这个技能是 2026-10-22 从横屏原版 `文戏编导提示词`（2026-10-21）改出来的。横屏原版原样保留，16:9 的戏照旧用它。
- 改了什么：站位、轴线、正反打、构图的规则按竖屏改（`rules.md` 里标〔竖屏〕的地方，加上新的 **V 节**）；剧设定改放 `竖屏制作\剧设定\`；检查脚本加了竖屏检查（V0 画幅和宽银幕词、V1 左右排开、V4 TALL FRAME）；看片脚本按竖画面拼图；填写示例改成了竖屏的拍法。节拍、表演、台词、质感这些和画幅无关的规则一条没动。
- **还没有一条文戏生成验证过，竖屏文戏更没有。**
  - 画面质感、光、资产行、平台这些规则来自打戏 v13（16:9），在打戏里验证过。
  - 节拍、表演、视线、正反打、镜头情绪这些是新写的，全部标"待验证"。
  - 竖屏构图来自《废土甜心》竖屏剧集的导演反馈（白模、成片里踩过的坑）和新的推测，都标了来源。
- 规则只写在 `rules.md` 一处。每条都标了来源：〔v13〕〔第22行〕〔废土甜心〕表示在别的戏里验证过或踩过坑，〔待验证〕表示新加的。
- `templates/填写示例_未验证.txt`（v3 换过）是《320磅》第 10 集段 1 的瘦身稿：17 秒 5 镜 3 句台词，8,116 字（v2 同一段 13,813 字），两个检查脚本 ❌ 0。还没生成过，只用来看格式和字数分配。第一条验证通过的竖屏文戏，放进新建的 `examples/`。`references/文戏设计.md` 里提到的"溪边告别"是旧示例，表格内容照样能看。

## 每次必做

1. **动笔前读** `rules.md`（先看 V 节和 R 节），再定是哪部戏：`竖屏制作\剧设定\` 里有这部戏，就照它抄风格锁、画面质感、特效质感的锁定句，台词语言也按它；只有横屏剧设定（`精品制作\剧设定\`）的，先做竖屏剧设定；都没有，就是新剧。这两种都走下面的"新剧第一次"。
2. **先设计，再写提示词**：节拍表、站位和视线（含谁近谁远、谁在上谁在下）、分镜表都在设计单里定好（`references/文戏设计.md`），提示词只负责翻译。
3. **以骨架为底写**：照 `templates/提示词骨架.txt` 写，标"照抄"的句子一字不差。
   - **v3 字数和台词（`rules.md` 文末 N 节、Q 节）**：有台词的段字数落在 **7,000–10,000 的区间**里，8,000 左右最稳，过了 14,000 才报 ❌——前十集 15,000 字以上的段台词丢了 30%，以下的只丢 1%。中文已经说过的，英文不再说（N2 的重复表照着删）；台词原文只在 Dialogue 行出现一次，逐拍和状态里不引用（Q2）；Dialogue 行写起止秒、紧跟在说这句的那一拍后面（Q4）。比区间长了按 N4 的顺序砍，**台词、剧设定固定句和特效定义、Restraint 这类验证过的特效句、可拍性写法不砍**。
   - **v4 场景卡（`rules.md` 文末 X 节）**：同一场戏分好几段时，背景和光会段段不一样（第 10 集前厅证据）。一集开写前先写 `第N集_场景锁.txt`：每场戏的总览资产行、每个方向的背景图资产行（没有人的单方向图，不用多格拼图）、【场景】块（地图、站位锚点、不入画）、每个方向一句 FACING 光句。每段照抄；每镜机位方括号以"方向N"开头。一集写完跑 `node "<本技能目录>/scripts/check_scene.js" <提示词文件夹>`，❌ 改到 0。
4. **交稿前检查，两步**：
   - **跑脚本**，查能数、能对原文的规则。❌ 全部改掉再跑，直到没有 ❌：

```
node "<本技能目录>/scripts/check_prompt.js" <提示词.txt>
```

   - **跑可拍性检查（v2）**：`node "<本技能目录>/scripts/check_shootable.js" <提示词.txt>`，❌ 全部改完（规则在 `rules.md` 的 P 节；机位从 `references/配方库.md` 选）。例外只有总控能批。
   - **派审查员**，查要读懂意思的那些：视线和轴线、正反打、表演写没写成看得见的信号、景别看不看得清、视线带不带镜头、运镜跟不跟情绪、台词、节拍和转折、竖屏同框和字幕位、资产齐不齐、人物和场景里的东西会不会多出来等，共 39 项，清单在 `references/审查清单.md`。没有 ❌ 以后，派一个轻量子 agent，只给它文件路径：

```
Agent(subagent_type: "general-purpose", model: "haiku", description: "审查竖屏文戏提示词",
      prompt: "先读 <本技能目录>/references/审查清单.md，照它审查 <提示词.txt 的完整路径>（有设计单就加上：设计单 <完整路径>）。只读，不改、不建任何文件。按清单里的交回格式交回。")
```

   - 审查员报的每一条，我对照原文核实：属实就改，不属实在回复里一句话说明；它看不准的我来判断。它没报的不等于没问题，交稿前我自己再过一遍这几项：
     - **F 视线**：在脑子里把正反打接一遍，两个人是不是在对视，视线高低对不对得上；
     - **E 表演**：每个反应是不是写成了看得见的身体信号，景别看不看得清（竖屏近景里手常常在画面外）；
     - **D7**：主观镜头从那个位置真的看得到吗；
     - **A8**：台词是不是用户给的原文，一个字没改；
     - **V1**：同框是不是纵深或过肩，没有左右站开。
   - 脚本和审查员的 ⚠️，保留的都在回复里用一句话说明为什么。改动大就重跑脚本，必要时再派一次审查员。

## 输入：只问 7 件事

0. **哪部戏**：`竖屏制作\剧设定\` 里有的照用；只有横屏剧设定的、或者新剧，走"新剧第一次"。
1. **多长**：10 秒建议 2–4 镜，15 秒建议 3–5 镜，最多 6 镜。
2. **谁在场，开场各在哪、什么状态**：站着还是坐着、带什么伤、手里拿着什么、开场是什么情绪。
3. **这一段讲什么**：两个人是什么关系、各自想要什么、藏着什么；有导演的原话就照原话。
4. **台词原文**：谁说、说什么。语言按剧设定（大部分戏英文，《宁小贤》中文）。没有台词就做无台词的戏，**我不编台词**。
5. **停在哪**：最后一帧谁在哪、朝哪看；什么还没发生（那句话还没说出口、还没转身、手还没松开）。
6. **资产清单**：场景、人物、群演、道具各有哪些参考图，平台上叫什么名字。我们做片资产通常是齐的：画面里出现的，有资产就都 @（规则 R1）。

第 0、1、2、5、6 件不能猜，没给就先问。第 4 件没给就按无台词做。其余照下表的默认，交稿时把用了哪些默认列出来，请用户确认：

| 项 | 默认 |
|---|---|
| 平台 | 放哪个项目第几行，先问；画面比例 9:16；分辨率 720p 或 1080p |
| 场景和光 | 场景由用户给。没说光源时，按场景定"有来源的光"（油灯、烛火、窗、天光），先把画面写暗 |
| 站位和轴线 | 两人一左一右，主角在左；整段不越轴。同框时主角离镜头近、在画面下方，另一人远一点、在画面上方（或者过肩） |
| 字幕位 | 脸放在画面上方约六成以内，下方留给字幕 |
| 台词语言 | 按剧设定：大部分戏英文（in American English）；《宁小贤》中文（in Mandarin Chinese） |
| 情绪走向 | 至少一次转折（不是从头到尾一种情绪） |
| 镜头参考 | 用户给了样片，先用 `scripts/shot_list.js` 拉片；没给就按"先纵深同框或过肩、再正反打、转折后再同框"排 |
| 资产 | 默认齐全：场景、人物、群演、道具都有参考图，画面里出现的每样一行资产行（R1）；场景写清独一无二的东西在哪、反打时尽头是什么（R2、R6）；群演写这一段几名、在干什么（R4）；每个有名字的角色只出现一次（R3） |

资产的外形以参考图为准。资产行只写尺寸、数量、状态，以及和参考图不一样的地方（规则 C4）；场景、群演、道具的写法见规则 R2–R5。背对镜头的人，资产行写"不采用参考图的正面朝向"（规则 E8）。各剧的资产表在它的剧设定里。

## 新剧第一次：先定竖屏剧设定

每部戏的风格锁、画面质感、特效质感都单独做一次，存进竖屏剧设定，之后这部戏的每一行竖屏提示词（文戏、武戏共用）都照抄锁定的句子。

- **已经有横屏剧设定的戏**（现在有《宁小贤》《废土甜心精品》）：拿横屏那份起草竖屏剧设定，风格锁照抄；风格锁里有宽银幕词（如《宁小贤》的"变形宽银幕，2.39:1"），先问用户竖屏要不要保留；画幅写 9:16，状态写"未验证（竖屏）"。用户确认后存进 `竖屏制作\剧设定\<剧名>.md`。
- **新剧**：
  1. 用户填 `templates/新剧输入卡.md`。有风格锁原文，就直接贴原文。
  2. 我按 `references/风格三件套.md` 起草：风格锁、画面质感、特效质感、结尾的英文风格复述和禁止项、这部戏常用特效的定义，并写上台词语言。竖屏的风格锁不写画幅和宽银幕词。
  3. 自查后给用户确认，英文部分用中文讲清。确认后存成 `竖屏制作\剧设定\<剧名>.md`，状态写"未验证"。
- 第一条生成后只验质感（`references/风格三件套.md` 第七节，竖屏多看一条：有没有上下黑边）。有问题改剧设定，不在单行里补；用户点头后，状态改成"验证过"。

## 流程

1. **收输入**：缺的先问。
2. **设计**（`references/文戏设计.md`），按顺序做：
   - 一句话：这一段讲什么；
   - 人物设定：想要什么、藏着什么、怕什么、谁占上风；
   - 节拍：每拍写触发、谁的情绪从什么变成什么、观众看到的信号、关系怎么变；
   - 秒级情绪表；
   - 站位和视线：左右、谁近谁远、谁在上谁在下、视线方向和高低（第五节、第十二节）；
   - 分镜：每镜的情绪任务、景别、机位、同框方式、运镜、切点理由。
3. **写提示词**：照骨架写。每镜写六件套；第 2 镜起，第一拍写切点类型（Cut on the look / Cut on the line / Cut on the reaction / Matched on action，意思是"切在视线、台词、反应、动作上"）；关键的反应写三层；【镜头衔接】里写 TALL FRAME 一句。
4. **自检**：见"每次必做"第 4 条。
5. **交付**：见下一节。不点生成。
6. **生成后**：
   - 用户把成片下载到本地，我用 `scripts/review_video.js` 抽帧看片，按 `references/平台与看片.md` 的竖屏文戏验收清单写问题表。重点看画幅、同框、视线方向、嘴型、表演大小、字幕、眼睛。
   - 只改用户点名的问题，改完再跑检查。
   - 某条写法被成片证明有效、用户点头后，去掉 `rules.md` 里那条的"待验证"，并用 `scripts/make_canon.js` 登记原句。

## 交付

- **提示词**：存成 `竖屏制作\视频N_名字_提示词.txt`。
- **设计单**：存成 `竖屏制作\视频N_名字_设计.md`，内容如下：
  - 开头一句：这一段讲什么，两人的关系从什么变成什么。
  - 节拍表：拍 / 秒 / 触发 / 谁的情绪从什么到什么 / 观众看到的信号（2–4 个）/ 关系怎么变（距离、谁占上风）。
  - 站位和视线：俯视站位（用文字画，标出机位、谁近谁远），加一张视线表（谁看画面哪边、高还是低）。
  - 分镜表：镜 / 秒 / 情绪任务 / 景别和机位 / 同框方式（纵深、上下、过肩、单人）/ 运镜（由什么情绪触发）/ 切点理由 / 最可能出错的地方，以及提示词里怎么防。
  - 改版时加"改了什么 / 没动什么"表；结尾一行写检查结果。
- **回复**（中文、大白话）：
  - 这一段一句话；
  - 检查结果：脚本和审查员各报了几个 ❌、几个 ⚠️，怎么处理的；
  - 用了哪些默认，要用户决定的事；
  - 看到了、没改的。
- **提醒上平台五件事**：画面比例设 9:16；时长和提示词一致；分辨率 720p 以上；这一行用到的场景、人物、群演、道具参考图都 @ 上了、名字和平台一致；台词语言对不对。

## 和别的技能怎么分

| 戏 | 竖屏 9:16 | 横屏 16:9 |
|---|---|---|
| 不打的戏：对话、对视、告别、等待、心事 | 竖屏文戏编导提示词 | `文戏编导提示词` |
| 人对人、对手和人差不多大的打戏 | `竖屏武戏编导` | `武戏编导` |
| 天上打几百米的巨物 | `竖屏比例差打戏` | `bilicha-daxi` |
| 一段里先说后打 | 拆成两行生成：说的那行用文戏，打的那行用武戏 | 同左 |
| 《废土甜心》竖屏剧集按集做 | storyboard / previs / seedance-prompt（`原项目工作区（未附）`） | — |

每部戏的竖屏剧设定不放在技能里，放在 `<项目根目录>/竖屏制作/剧设定/<剧名>.md`，竖屏文戏和竖屏武戏共用。工作文件夹 `<项目根目录>/竖屏制作/` 的 `CLAUDE.md` 写了这套竖屏技能怎么分工。

## 规则怎么长大

- 看片发现新坑：在 `rules.md` 对应条目下加一行"坑"；没有对应条目就加一条。能用脚本查的，加进 `check_prompt.js`。
- 某条写法生成验证通过、用户点头后，去掉"待验证"；被成片证明不行的，改掉或删掉，并在坑里写清原因。
- 第一条竖屏文戏验证通过：新建 `examples/` 放进去，跑 `make_canon.js` 登记原句；骨架里照抄的句子换成它的原句。
- 剧设定里锁定的句子：要改先问用户，改了这部戏后面每一行都跟着改；新剧第一条成片验完质感、用户点头，状态才改成"验证过"。
- 改规则先问用户：规则都来自用户的验收。
- 竖屏验证出来、对横屏也成立的写法，问过用户再同步到横屏原版。
