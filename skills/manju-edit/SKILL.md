# 漫剧剪辑

用户在一家做 AI 漫剧的公司做剪辑。素材是 AI 生成的视频片段（一条 10–30 秒、内部自带多个镜头），在剪映专业版里剪成 1–2 分钟一集，交付前要过公司的十条剪辑要求。

这个 skill 干五件事，先分清用户要的是哪件：

| 用户说 | 走哪个流程 | 先读 |
|---|---|---|
| "按分镜剪""粗剪""把这几段剪成一集" | 工作流一：基础剪辑 | `references/storyboard-cut.md` 第一部分 |
| "精剪""深度精剪""剪得更好看""更出彩" | 工作流二：深度精剪 | `references/storyboard-cut.md` 第二部分 |
| "帮我检查这一集""能不能交""过一遍规范""有没有夹帧" | 工作流三：交付前自检 | `references/company-rules.md`、`references/frame-residue.md` |
| "这条素材不行""这个镜头怎么救" | 工作流四：兜底 | `references/rescue-playbook.md` |
| "加音效""配乐""声音太假""合成个音效""现做音乐""做一段循环配乐" | 工作流五：声音 | `references/sound-design.md` |
| "写成剪映草稿""在剪映打开""生成草稿" | 写草稿（工作流一、二的最后一步） | `references/write-draft.md` |
| 预告片 / TK 交付 | 见文末两节 | `references/company-rules.md` |

所有流程都靠同一套脚本先把草稿和画面"读"出来。不要凭文件名和想象下判断：先跑脚本、看接触表，再说话。

## 重点：夹帧和卡帧

公司第 2 条：「要避免出现画面夹杂几帧不相干的画面，剪辑就是要精确到每一帧。」这是最常犯、审片最常退回的错。

- **夹帧（残帧）**：镜头头尾多出 1–3 帧不属于它的画面。最常见的来源是入出点压在 AI 素材内部切点上，差 1 帧就带进别的镜头。其次是 AI 换镜头时留下的混合帧、坏帧、半边黑。
- **卡帧**：镜头头尾几帧一模一样、停住不动，像卡了一下。常见于 AI 起幅僵直、素材末尾卡住。

**每一次**剪完、改完、交付前都要查，不能省。`qc_draft.mjs` 默认就查：读每段用到的原始素材，报出哪一段、头还是尾、几帧、拖哪条边、拖几帧。导出后用 `qc_media.mjs` 再查一遍成片。成因、校准数据、在剪映里怎么改、机器查不到什么，都在 `references/frame-residue.md`。

## 工具

都在 `scripts/` 下，只需要 Node 18 以上，不用装任何包、不需要 Python；读画面和素材的脚本另外需要 ffmpeg / ffprobe 在 PATH 里。Windows 和 macOS 的剪映草稿目录都能自动找到。

| 脚本 | 做什么 |
|---|---|
| `list_drafts.mjs [名称]` | 列出本机剪映草稿、路径、时长、能否直接读、有哪些时间线 |
| `backup_drafts.mjs [名称]` | 把还是明文的草稿时间线 JSON（不含媒体）备份出来。新下载的草稿先跑它，再打开剪映 |
| `dump_timeline.mjs <草稿> [--all] [--from 秒 --to 秒]` | 把时间线打印成可读的剪辑表：观众实际看到的画面（多轨压平）、每段的源入出点/变速/缩放/镜像/原声，各音频轨、字幕。`--all` 连停用片段和隐藏轨一起看 |
| `qc_draft.mjs <草稿> [--no-media]` | 交付自检：按十条要求查时间线，输出 ✗ 违规 / ! 疑似 / ? 待确认，带时间码；末尾列出全部字幕供校对。规则 2 默认读原始素材查头尾残帧（`--no-media` 只查时间线结构） |
| `qc_edges.mjs <草稿 或 mp4>` | 只查头尾残帧（夹帧、卡帧），输出比 qc_draft 里的更细；给 mp4 时只看画面 |
| `qc_media.mjs <mp4> [--out 目录]` | 成片或单条素材体检：镜头切点表、夹帧（单独成段的、粘在镜头头尾的、混合帧、镜头中间坏帧）、卡帧、黑场、静帧、无声洞、声音硬切、响度峰值；导出逐镜头接触表（每镜头首/中/尾帧） |
| `qc_media.mjs <mp4> --strip 秒,秒` | 导出指定时间点前后的逐帧条（12 帧，标帧号）。凡是要写进报告的夹帧、卡帧，先用它看过再下结论——2 帧以上的"画面突变"多半是切点后紧跟快动作或甩镜头，"突然变亮"可能是闪光也可能是夹进来的别的画面 |
| `audio_in_export.mjs <草稿> <成片>` | 核对时间线上每段声音在成片里是否真的听得到（导出后少了对白/音效时定位） |
| `stats_drafts.mjs <草稿根目录>` | 对一批定稿做操作统计，用来刷新 `references/house-style.md` |
| `write_draft.mjs <方案.json> [--dry-run]` | 把剪辑方案写成一条新的剪映草稿：原素材带余量，声音、字幕分轨。只新建、不覆盖。剪映开着时不碰草稿列表，关掉后跑 `--register <草稿名>`。格式和流程见 `references/write-draft.md` |

`<草稿>` 可以是草稿文件夹路径，也可以是草稿名的一部分（如 `校园17`）。读画面的公共部分在 `scripts/lib/frames.mjs`（切点、残帧、卡帧），对着草稿查素材的在 `scripts/lib/edges.mjs`。

另有两个 Python 脚本，只能在装了 Surge XT 和 pedalboard 的机器上跑（见工作流五）：`scripts/sound/surge_sfx.py` 做设计类音效，`scripts/sound/surge_music.py` 写连贯配乐。

### 读草稿前要知道的三件事

1. **加密**：剪映 6 以上只要在本机打开过草稿，就会把 `draft_content.json` 改写成加密的。能直接读的只有刚从云端/小组空间下载、还没打开过的草稿。所以拿到新下载的草稿，**先跑 `backup_drafts.mjs`，再让任何人打开剪映**（备份目录在脚本输出的最后一行；默认是用户主目录下的 `漫剧剪辑/草稿JSON备份`，可用环境变量 `MANJU_DRAFT_BACKUP` 指到别处）。读草稿的脚本遇到加密会自动改用最近一次的明文备份，并提示备份时间——**备份之后在剪映里做的改动是看不到的**，报告里要写明"查的是 X 月 X 日 X 点的版本"；用户说刚改过，就请他从云端重新下载一份（或导出成片改查成片）。没有备份也读不了时别硬猜。素材文件还在剪映的草稿文件夹里，读备份时脚本会回去那里找素材。
2. **多时间线**：一条草稿常有"正片 + 备份"几个时间线，根目录的 json 只对应其中一条，不一定是正片。先看 `list_drafts.mjs` 列出的时间线名，再用 `dump_timeline.mjs` 的时长和用户说的片长对一下。
3. **停用片段和隐藏轨**：脚本默认不统计停用片段。隐藏的文字轨可能用于无字幕版，也可能是审片批注；交付前按项目要求确认。

## 工作流一：基础剪辑（按分镜剪）

用户给了分镜脚本和生成好的各段素材，要剪成一集时走这个流程。步骤、镜头对照表的格式、"接法"怎么落刀，见 `references/storyboard-cut.md` 第一部分。要点：

1. 读分镜脚本：分镜表、生成段切分、英文台词总表、后期清单。
2. 每段素材跑 `qc_media.mjs`，拿内部镜头表、接触表、头尾残帧。
3. 出**镜头对照表**：素材里每个内部镜头对到分镜哪个镜号，标出对上了 / 景别不对 / 缺镜 / 多出来 / 顺序反 / 穿帮。
4. 每个镜号定取用区间：入点在素材内部切点之后至少 1 帧，出点在之前至少 1 帧；台词说完再留几帧。
5. 按分镜"接法"一列落刀（看 / 动 / 因果 / 交代 / 段首）。
6. 台词、字幕、音效清单（分镜"声音"列 + 后期清单）、后期清单里的特殊处理。
7. 做不到的先兜底（工作流四），救不了写补拍需求。
8. 交付前自检（工作流三）。
9. 写成剪映草稿并打开（`write_draft.mjs`，见 `references/write-draft.md`）。

## 工作流二：深度精剪

基础剪辑已经没有错、关掉音乐也能看（规则 5）之后，才做精剪。按 `references/storyboard-cut.md` 第二部分的八遍走，每遍只看一件事：重音、去水、反应、连贯、画面加工、声音设计、开头结尾、整集过一遍。可以调顺序、长短，加反应镜头，重复用镜头；不加新剧情、新台词，不破公司十条。交付物是**精剪改动表**：每一刀改了什么、为什么。精剪改的刀多，最后一定逐帧看每个改过的接缝。定稿后同样写成剪映草稿（`references/write-draft.md`）。

## 工作流三：交付前自检

用户说"帮我检查这一集""能不能交""过一遍规范"时走这个流程。

1. `list_drafts.mjs` 找到草稿，确认读的是正片时间线。
2. `qc_draft.mjs <草稿>`。规则 2 下的"头尾残帧"是读原始素材查出来的：哪一段、头还是尾、拖几帧。素材找不到的段会在末尾列出来，那几段只能靠成片查。
3. 有导出成片就再跑 `qc_media.mjs <成片>`；没有就问用户能不能导一版（十条里的穿帮、夹帧的一部分、声音截断只有成片能查实）。两个脚本报在同一时间码的问题互相印证，优先报。
4. **夹帧、卡帧逐条核实**：每一条 `!` 和 `?` 都用 `qc_media.mjs <成片> --strip 秒数` 看逐帧条；没有成片就请用户在剪映里把播放头放到那个时间码，用 ←/→ 逐帧看。核实过的写进"必须改"，没核实的写进"需要你看一下"。
5. **看接触表**：用 Read 打开 `sheet_NN.jpg`，逐镜头看穿帮（手指肢体、画面里的文字、道具左右、服装连续、镜像后的反字）、接缝前后帧是否相干、景别是否跳。这一步不能省——规则 7 和"和本镜头很像的残帧"脚本查不出来。
6. **校对字幕**：`qc_draft.mjs` 末尾列出了全部字幕。逐条读，找错别字、同音字、漏字、人名前后不一致；有台词本就对台词本。再对着接触表看两件机器看不全的事：
   - **断句和换人**：识别出来的字幕常把一句话从中间劈开，或者把两个人的话并进一条（实例：`strong psychological suggestion do you` / `believe in ghosts I only believe evidence`，其实是女警说完、男人问"do you believe in ghosts"、女警答"I only believe evidence"）。接触表上字幕没换、说话的人换了，就是这种情况。脚本会按逐词时间报"中间停了 N 秒"并给出拆分时间码，但素材内部换镜头的它看不到。
   - **看得清吗**：字幕压在亮的背景上（窗户、白墙、白衣服）时读不读得出来。没按标准加描边的字幕在这种地方最先出问题。
7. 把 `?` 级别里靠时间线就能判断的自己先判掉（用 `dump_timeline.mjs --from --to` 看那一段），剩下真要人去听、去看的再留给用户。
8. 出报告。

### 报告格式

按"要不要改"排，不按脚本输出顺序排。每条都给时间码（`分:秒:帧`，和剪映时间线一致）和在剪映里的具体做法。

```
# 第N集 交付自检

结论：能交 / 改完 X 处能交 / 不能交（原因一句话）

## 必须改（违反公司要求）
- 00:25:18 【规则2 夹帧】「第七集片段2」开头 1 帧是素材里上一个镜头的画面（逐帧条已核实）→ 这一段左边缘向右拖 2 帧
- 00:58:19 【规则2 夹帧】上层两段之间漏出下层 2 帧「分镜3-2」→ 把上层后一段的左边缘向左拖 2 帧盖住
- ...

## 建议改
- 00:46:23 【规则2 卡帧】镜头开头 5 帧停住不动 → 入点往后挪 5 帧
- ...

## 需要你听/看一下的
- 01:12:05 对白「……」的尾音可能被剪掉：声音片段在字幕结束前 6 帧就断了
- ...

## 没问题的
规则 1、6、9 通过（一句话带过）

## 我没查到的
（没有成片所以没看画面 / 有 N 段素材本机找不到，那几段的头尾残帧没查 / 没有台词本所以错别字只按语感查 / ……照实写）
```

脚本说"通过"只代表机器能查的那部分没发现问题。报告里不要把"脚本没报"写成"没有问题"，尤其是规则 5、7、错别字，以及和本镜头很像的残帧。

## 工作流四：兜底

用户说"这条素材不行""这个镜头怎么救""生成的和想要的不一样""帮我把这段剪顺"时走这个流程。

1. **弄清想要的效果**：这个镜头在戏里的作用、要多长、接在谁后面、台词是什么。有分镜脚本就从分镜里读；用户没说也没有分镜就问——没有目标就谈不上差距。
2. **看素材**：对每条相关素材跑 `qc_media.mjs`，看镜头表、接触表和残帧报告。AI 长条素材内部有好几个镜头，先把每个内部镜头的起止时间码和内容列出来，标出干净可用的区间和坏掉的区间（变形、闪烁、混合帧、卡帧、自带字幕、僵直）。
3. **定症状，选手法**：读 `references/rescue-playbook.md`，按"能挑就不修，能修就不补，补不了才重生成"的顺序选。同一个问题手册里通常给了几种解法，选副作用最小的，并过一遍手册末尾的副作用清单。
4. **出剪辑方案**，格式见下。入出点避开内部切点至少 1 帧。
5. 剪辑救不了的，按手册 D 节写重生成需求，不要给一个勉强的方案充数。

### 剪辑方案格式

一行一个画面片段，按成片时间顺序；声音单独列。数值给到剪映里能直接填的程度。

```
# 第N集 · 场X 剪辑方案（目标时长约 Ns）

## 画面
| # | 素材 | 取用区间(素材内) | 成片时长 | 处理 | 为什么 |
|---|------|------|------|------|------|
| 1 | 分镜3-1.mp4 | 02.10–04.60 | 2.5s | 缩放105% | 0–2s 起幅僵直掐掉；4.6s 后手部变形 |
| 2 | 分镜3-2.mp4 | 11.00–12.40 | 2.0s | 0.7x 慢放+补帧，缩放130%，镜像 | 反应不够长；原景别太松；视线要接左 |
| 2' (叠盖) | 分镜3-4.mp4 | 06.20–07.50 | 1.3s | 盖在 #3 的 00:05:10 起 | 盖住 #3 抽帧后的跳点，对白留在下层 |

## 声音
- 对白：#1、#3 音频分离；#3 的尾音拖过切点 8 帧（L cut），头尾淡变 0.3s；原声 +10dB
- AI 自带音乐：#2 人声分离只留人声
- 音效：00:02:15 「拳头攥紧」对准握拳那一帧；00:04:20 「影视 重音 悬疑」压反应特写；全段铺「背景的风声」−12dB
- 音乐：最后加。这段先不给，等画面声音自己成立

## 剪不出来的（需要重生成）
- 缺一个 A 的近景反应（约 2s，面朝左，无台词，不要背景音乐）……

## 改完后自查
- 逐帧看 #2/#3 接缝；镜像后检查画面里的字和佩刀左右；跑 qc_draft 看头尾残帧
```

"为什么"一栏不能省：公司的要求是每一刀都有理由，用户拿这张表去剪、去回答审片人的时候用得上。

## 工作流五：声音

音效和配乐。读 `references/sound-design.md`。三条硬规矩：

- **写实的声音不用代码合成**。脚步、衣服、门、纸、水、风、打击声，从录音素材库找（剪映音效库、Sonniss 音效包），或者用 AI 对着画面、按文字生成。用正弦波和噪声拼出来的一听就假，换多好的合成器也一样。
- **合成器只做设计类声音**（重音、呼、上升音、低频轰、悬疑长音），而且用真正的合成器（Surge XT），不用代码直接拼波形。
- **每个生成或合成的声音，人听过才进片**。

质感的大半来自进片前的处理：剪干净、对准动作帧、同一场戏放进同一个空间（混响）、远近、给对白让出中频、对白 > 音效 > 音乐、全片响度统一。

**强调点类声音（重击、咚、呼、上升音、悬疑长音）先用合成器现做**，剪映音效库是备选，脚本里没有的声音再去库里找。这是 2026-11-21 用户听过样品定的：比以前用代码拼的好，比去剪映找、下载方便。合成器 Surge XT 已装在本机，`scripts/sound/surge_sfx.py` 一条命令出这五种 WAV，时长和音高按镜头定（`riser len=72f hit pitch=-3`）；五种以外的声音写一份 JSON 配方现做。

**配乐先用合成器现写**，剪映曲库是备选（2026-11-21 用户听过样品说能用）：`scripts/sound/surge_music.py <输出.wav> mood=悬疑:12,打戏:30,悲伤:45 hits=12,21`。全程一个调、一个速度、一条贯穿旋律，换情绪的点落在切点上，开头和结尾都写好，也能做无缝循环。台词密的段落加 `melody=off`。

这两个脚本要用 `D:\漫剧公司\工具\音频\py311` 里的 Python，用法和脚本控制合成器的坑见 `sound-design.md` 第三节。做出来的声音照样要人听过才进片。其他外部工具（音效库、AI 生成模型）还没装。要用哪个先问用户，下载前说清楚文件名、来源、大小、能不能商用。

## 预告片

先确认用户的项目规范，再根据需要使用下面的预告片工作流：

- **先搭音乐再铺画面**：按内容和情绪分段（示例是 50 多秒分 3 段：危机悬疑 → 温情 → 危机升级加反击），每段一段音乐，段间衔接自然；然后按音乐节奏铺镜头。
- **三条时间线**：时间线1 用子草稿/复合片段把各集正片按顺序铺开（这里的复合片段是允许的）；时间线2 粗筛素材并分类（双击进复合片段复制原始片段，不能直接拿复合片段）；时间线3 才是预告片。
- 四条硬要求：不剧透关键剧情和结局；必须分段；主角和关键角色多出现、龙套少出现；对白、音效、音乐互不干扰（对白不叠、音效不压对白、音乐不高过对白）。

帮用户做预告片时，交付物是一张分段表：每段的情绪、音乐、时长，下面列镜头（来自第几集的哪个时间码、用多长、为什么选它），并单独标出"这个镜头会不会剧透"。预告片镜头切得碎，交付前同样要查夹帧。

## 改草稿这件事

**新建草稿**：剪完默认用 `write_draft.mjs` 写成一条新的剪映草稿并打开（用户 2026-11-21 定），流程见 `references/write-draft.md`。它不碰已有草稿。

**改已有草稿**：默认交付物是上面的报告和方案，由用户在剪映里动手。原因：本机保存过的草稿是加密的，直接改 json 既不可靠，也容易把草稿弄坏。

用户明确要你代为操作时，用桌面控制在剪映里操作，并遵守：

- 动手前把草稿文件夹整份复制备份，并在剪映里复制一条"备份"时间线。
- 往输入框打字前先单击再双击聚焦，不确定焦点在哪时不要按 Ctrl+A、Tab、Home/End——焦点在时间线上时这些键会选中/移动/删除整条时间线。
- 每做完一处回到那个时间码逐帧（←/→）检查接缝。
- 不买会员、不点"一键替换 VIP 素材"、不重新链接或删除素材；遇到这类弹窗取消并告诉用户。
- 预览时临时隐藏或静音的轨道，结束前恢复。

## 说话方式

- 时间码用 `分:秒:帧`，和剪映时间线读数一致；素材内的入出点用秒。夹帧报告里分清"素材帧"和"时间线帧"。
