# 写剪映草稿

剪完一集，把结果直接写成一条**新的**剪映草稿，用户打开就能接着改。2026-11-21 用户定：这比只交成片、或手动往剪映里导素材方便，以后剪完默认这样交。

脚本是 `scripts/write_draft.mjs`。它只新建草稿，不改、不覆盖任何已有草稿。

## 流程

1. 按工作流一、二定好每一刀，写一份**方案**（`方案.json`，格式见下）。
2. 只检查，不写文件：

   ```
   node write_draft.mjs 方案.json --dry-run
   ```

3. 写草稿。剪映关着时会同时加进草稿列表；开着时只写草稿，列表留到第 5 步：

   ```
   node write_draft.mjs 方案.json
   ```

4. **打开之前**跑 `qc_draft.mjs <草稿文件夹>`，有 ✗ 就改方案，换个名字重写。草稿一被剪映打开，时间线就加密了。脚本已经留了明文备份，之后的 `qc_draft`、`dump_timeline` 会自动读备份，但读不到用户在剪映里的新改动。
5. 剪映开着的话，**先问用户能不能关**，别替用户关：用户可能正在改别的片子。关掉后：

   ```
   node write_draft.mjs --register "草稿名"
   ```

6. 打开剪映，点开这条草稿，看这几样：有没有"媒体丢失"、轨道数和总长对不对、抽几个时间点看画面和字幕、放大过的镜头构图对不对。
7. 告诉用户草稿名，哪些镜头没有余量，哪些声音还没人听过。

## 方案格式

```json
{
  "name": "圣诞礼物01-精剪v1",
  "fps": 24,
  "canvas": [1080, 1920],
  "muteVideo": true,
  "video": [
    { "label": "镜1", "file": "D:/素材/段1.mp4", "inFrame": 87, "outFrame": 126 },
    { "label": "镜2黑场", "black": 14 },
    { "label": "镜3", "file": "D:/素材/段2.mp4", "in": 2.34, "out": 3.96, "crop": [0.33, 0.12, 0.67] },
    { "label": "镜4", "file": "D:/成品/镜4_合成.mp4", "as": "镜4_瞳孔倒影.mp4", "inFrame": 0, "outFrame": 92 }
  ],
  "audio": [
    { "name": "对白", "role": "dialog", "clips": [{ "file": "D:/声音/对白.wav", "at": 2.10, "in": 2.10, "out": 3.40 }] },
    { "name": "音效", "role": "sfx", "clips": [{ "file": "D:/声音/hit.wav", "at": 5.0 }] },
    { "name": "配乐", "role": "music", "clips": [{ "file": "D:/声音/配乐.wav", "at": 0, "in": 0, "out": 139.75 }] }
  ],
  "text": [
    { "name": "英文", "style": "en", "cues": [{ "text": "Dad, stop it", "a": 2.13, "b": 3.08 }] },
    { "name": "中文", "style": "zh", "cues": [{ "text": "爸 你住手", "a": 2.13, "b": 3.08 }] }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `video` | 按顺序首尾相接，不写时间线位置 |
| `inFrame` / `outFrame` | 素材里的入点、出点（帧）。出点那一帧不算。也可以写 `in` / `out`（秒），会取整到帧。**能写帧就写帧** |
| `black` | 一段黑场，写帧数 |
| `crop` | `[x, y, h]`，取景框左上角和高度，都是占画面的比例，宽度按画布比例算。写成剪映里的缩放和位置，用户还能调 |
| `speed` | 变速，比如 `0.5`。**还没在剪映里打开验证过**，用了要逐帧看。要光流补帧的慢放先渲染成片段再放进来 |
| `as` | 复制进草稿时用的文件名，给做过效果的片段起个看得懂的名字 |
| `muteVideo` | 画面的原声全关。声音已经单独混好时必须开，不然同一句话会响两遍。单段可以写 `mute` |
| `audio[].role` | `dialog` 对白、`sfx` 音效、`music` 音乐。`qc_draft` 靠它查音效和字幕同步，顺序按对白、音效、音乐排 |
| `clips[]` | `at` 时间线位置（秒），`in` / `out` 文件内区间（秒），`volume` 音量倍数（可选）。同一轨不能重叠 |
| `text[].style` | `en` 是公司《字幕标准》：字号 8、描边 40、行间距 10、Y -465，超过 40 个字符自动折成两行，全角省略号换成 `...`。`zh` 是参考中文，放在英文下面。也可以写对象：`{"base":"zh","size":6,"y":-0.5}`，还能写 `stroke`、`lineSpacing`、`color`（`[r,g,b]`，0–1） |
| `cues[]` | `a` / `b` 秒，或 `aFrame` / `bFrame` 帧 |

## 怎么排才好改

- **画面用原素材，不用切好的成片段。** 这样用户拖边缘能找回前后的画面。只有合成、修图、光流慢放这种做过效果的镜头才放渲染好的片段，并告诉用户这几镜没有余量。
- **声音已经混好时**：一条混音拆成现场声、旁白、音效、配乐几轨。现场声按镜头切，旁白按句切，这样挪镜头时声音能跟着挪。
- **TK 交付要纯英文**：中文字幕放单独一轨，导出前隐藏。

## 做不到的

文字和画面的动画（淡入淡出）、转场、特效、滤镜、关键帧、复合片段都还不支持。需要的话写在交付说明里，让用户在剪映里加，或者先渲染进片段。

## 为什么这样写（改脚本前先看）

都是 2026-11-21 在剪映专业版 11.8（Windows）上踩出来的：

- 格式照剪映自己存的明文 `template.json.bak`（`is_minimal_draft: true`）。其他版本没试过，脚本会提醒。
- **素材路径要绝对路径**。写相对路径，剪映报"媒体丢失"。
- **剪映不扫描草稿文件夹**，新草稿要写进 `root_meta_info.json`，`draft_ids` 加 1。这个文件剪映开着时会反复重写，所以只能在它关掉后改。脚本改之前会备份到 `草稿JSON备份/_草稿列表备份/`。
- 音频片段 `visible` 要是 `true`，`false` 就是停用片段。
- 入点按微秒向上取整再加 2 微秒，防止剪映向下取帧时落到上一帧（见 `frame-residue.md`）。
- Node 24 的 `fs.rmSync` 碰到中文路径会崩，这个脚本里不要用。

**验证到哪一步**：用这个脚本重写《黑帮老大的圣诞礼物》第一集，256 个片段和已经在剪映里打开核对过的草稿逐项一致（只差随机 ID 和机器信息）。"加进真实草稿列表"这一步是手工跑通后写进脚本的，脚本本身只在列表副本上测过。变速没有打开验证过。
